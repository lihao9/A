# UI 链接：空表 → 项目链接 → 扫描填入（准确性规则）

> 本目录模块文档的「链接登记表」**默认留空**。  
> **写代码 / 对稿实现前**必须先有可用 UI 链接；空表时按本文流程处理。  
> 扫描**不能**替代使用者确认。名称匹配无法保证 100%；**准确靠流程门禁**，不是靠猜。  
> 确认画板之后还要填元素对照表和视觉变量表，见 [`AGENT实现约定.md`](./AGENT实现约定.md) §9。

---

## 1. 文档阶段 vs 实现阶段

| 阶段 | UI 链接表 |
|------|-----------|
| 只写需求 / UE / 接口 | **保持空**（状态=未提供），不预填 Figma |
| Agent **开始实现某模块** | 先检查该模块链接表 |

---

## 2. 实现时：链接为空怎么做

1. **停止对该模块的 UI 实现**（UE/接口骨架可继续，但不得凭感觉画布局、下切图）。  
2. **提示使用者提供 Figma 项目链接**（整文件即可，例如 `figma.com/design/{fileKey}/...?node-id=1-2`），不必先逐页给 layer。  
3. 拿到项目链接后：按 §3 扫描 → 按 §4 匹配 → **先输出对照表请使用者确认**。  
4. 使用者确认（或纠正）后，再写入该模块链接登记表，然后才对稿实现 / 下 3x PNG。  
5. 若使用者明确说「无稿、按默认壳」：链接表状态改为「无稿按默认」，才可用文档默认布局规则，仍不得编造切图。

提示话术（可原样用）：

```text
本模块「链接登记表」为空，无法对稿实现。
请提供该产品 Figma 项目链接（整文件即可）。
我扫描后会给出「文档页面 ↔ 画板」对照表，确认后再填入文档并开始 UI。
```

## 3. 扫描范围

- 只扫 **Frame 画板名**（页面级），不把组件库里的「表单输入=手机号」当成页面。  
- **排除**画板名含：`不用`、`暂时不用`、`废弃`、`封面`、`组件`（整页组件盘）、明显非本模块（如还款/授信混在同一文件时，用本模块关键词过滤）。  
- 同一职责多状态（未输入 / 已输入 / 错误）：**全部列入该行**，禁止只留一张当「主稿」。

### 3.1 组件集变体 ≠ 页面上有（禁止误判）

Figma 文件里的 **COMPONENT / COMPONENT_SET**（如「导航栏专用图标」里同时有 `PrestaQ_Ico_Service` 和 `PrestaQ_Ico_Message`）是**设计系统库存**：库里有变体，只表示设计师预留了样式，**不表示当前页面画板上摆了这个入口**。

必须同时满足才算「页面上有」：

1. 打开的是**页面级 Frame 画板**（该模块链接登记表已确认的那张），不是组件盘、不是组件集本体；  
2. 在该画板的**实例图层树**里，能看到对应 INSTANCE，且 `componentId` 指向那个变体（或父实例展开后子层指向它）；  
3. 该图层当前可见（未被实例属性关掉、opacity 不为 0、未藏在关闭的 variant 开关后）。

**禁止：**

- 用 MCP/导出数据里的 `COMPONENTS` 清单当页面功能清单；  
- 因为组件集里有 Message / 优惠券 / 未读角标，就在需求里加消息入口；  
- 让设计从组件集里删掉「目前首页没用到」的变体——库要给其它页、后续迭代留，删了反而更乱。

后续真要加消息入口：以**新确认的页面画板实例**为准，再给元素编号、改模块文档；在那之前文档不得预写该入口。

判断拿不准时：把画板链接和「图层树里实际引用了哪个 componentId」列给使用者，等确认；不要自行脑补「库里有所以功能有」。

## 4. 匹配规则（保证「不乱填」）

每个模块文档登记表里的「页面」是**职责名**。匹配必须同时满足：

| 条件 | 要求 |
|------|------|
| 正向关键词 | 画板名包含该职责约定的关键词（见各模块登记表「匹配关键词」，无则用职责中文名） |
| 负向关键词 | 不含排除词（见 §3）及易混职责词（例：登录密码页不得误配「交易密码」） |
| 唯一性 | 同一职责下，无冲突的其它模块画板 |

**置信度：**

| 档 | 何时 | Agent 可否自动写入文档 |
|----|------|------------------------|
| 高 | 画板名与职责几乎同义，且无易混项 | 可写入，仍须在对照表里列出等确认 |
| 中 | 同职责多状态，或名称带场景后缀但主题明确 | 全部作为该行多链接写入，等确认 |
| 低 | 关键词弱、或命中多个不相关画板、或 0 命中 | **禁止写入**；列出候选，请使用者点选 |

**禁止：**

- 用「看起来像」的邻近画板顶替未命中页  
- 把「登录注册-开始页（不用）」填进手机号页  
- 把交易密码 / 删除账号验证 填进登录 OTP  
- 未确认就开始按扫描结果写布局

## 6. 准确性说明（给使用者）

自动扫描**做不到数学上的 100%**，因为设计稿命名可能不规范、一页多名、弹层叠在页面里。

能保证的是：

1. **不瞎填**：低置信度不入库。  
2. **不漏状态**：多态全部挂上，避免只做默认态。  
3. **有门禁**：写入文档与写 UI 都在你确认对照表之后。  
4. **可纠偏**：你改一行 node-id，以你的指定为准。  

因此「准确」= **关键词硬匹配 + 排除废稿 + 你确认一眼**，而不是 Agent 单方面保证 100%。

## 7. 确认画板之后（全模块）

登记表填完仍不能开始对着感觉写样式。必须继续：

1. 按 [`AGENT实现约定.md`](./AGENT实现约定.md) 用**功能**给元素编号，填该模块元素对照表（最终文案以确认稿为准）；  
2. 把颜色、字重、主次按钮样式填进视觉变量表（最终样式以确认稿为准）；  
3. 对照阶段用过的稿若与本次确认链接不是同一套，**作废**，全部按新链接重取。
