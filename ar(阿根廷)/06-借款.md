## 写法约定

1. 接口路径写作 `ori: /xxx`；实际 path 从 `00` §6 指定的本包 API 文档映射。
2. 字段只写 `o_xxx`；真实 wire 从 `00` §6 本包 API 映射。协议语义和枚举可保留。符号与分层按约定 §3。禁止对照工程混淆字段。
3. 本文的 `L-*` 仅是文档职责 ID，不要求实现为同名 Kotlin 符号。
4. 金额协议值按字符串接收和透传；展示统一交给本包金额格式化器。金额选择步进只在 03 首页执行；本模块不得自行计算利息、费用、到账额或应还额。
5. 可见文案、颜色、字重、尺寸以可执行阶段确认的 UI 为准。未确认前不得自编西语。
6. 本文已按使用者确认锁定：**无优惠券、无保险、无借款用途、无预提交待核销、无独立打款成功页、处理中页不轮询**。

## 1. 关键定论与术语

### 1.1 不可猜的业务定论

1. 所有进入借款确认页的路径，最终都必须拿到一份成功且 `data != null` 的借款预览。
2. 首页已经预览成功并交付内存数据时，确认页直接消费，不重复请求。
3. 04 授信交棒、进程重建或内存预览缺失时，确认页用入口产品 ID + 金额请求预览；失败回首页根。
4. 自动提单卡在倒计时内点击时，预览请求额外带预订单 ID；普通申请不带。
5. 收款账户列表单独调用银行卡列表接口，**不使用**预览响应里可能存在的银行卡数组。
6. 手动提交顺序固定：收款账户 → 交易密码 → 下单。
7. 自动提单倒计时结束：仍要求已有收款账户，但跳过交易密码，提交 `o_autoLoanStatus=1`。
8. 预览响应的金额、费用与计划只展示，不在客户端相互推导或校验加总。
9. **下单响应**的失败 `o_reason` 不传给失败页，因此该入口展示 UI 默认失败文案；03 首页/后续历史若已有失败原因，则仍传给同一失败页优先展示。
10. 下单状态 `1` 不进成功页；关闭确认页并回首页，由 03 的栈顶刷新取得最终订单状态。
11. 打款处理中页不轮询；页面返回首页后再刷新。
12. 自动提单取消成功后只转为手动模式，不自动离开确认页，不自动下单。

### 1.2 术语

| 术语 | 含义 |
|------|------|
| 普通申请 | 首页产品/金额申请，预览请求无预订单 ID |
| 自动提单卡 | 03 首页 `o_preLoanInfo` 卡；倒计时内可点进确认 |
| 自动提单进行中 | 预览返回 `o_autoLoanStatus==1`，确认页正在倒计时 |
| 手动模式 | 预览未开启自动提单，或用户已成功取消自动提单 |
| 入口金额 | 首页选择金额、自动提单卡金额、或 04 交棒的可借金额 |
| 预览 | `ori: /loan/pre/info` 返回借款确认所需数据 |
| 下单 | `ori: /loan/confirm` 正式提交借款 |
| 打款状态 | 下单响应的即时结果；不要和 03 首页订单展示状态混用 |

### 1.3 两套状态严禁混用

| 来源 | 字段 | 取值 | 含义 |
|------|------|------|------|
| 下单响应 | `o_loanStatus` | `-1` / `0` / `null` | 打款处理中 |
| 下单响应 | 同上 | `1` | 本次提交即时成功；回首页 |
| 下单响应 | 同上 | `2` | 打款失败；进失败页 |
| 首页上一笔订单 | `o_orderStatus` | `0` | 打款中 |
| 首页上一笔订单 | 同上 | `1` | 打款失败 |
| 首页上一笔订单 | 同上 | `2` / `3` | 成功未结清，进入还款职责 |
| 首页上一笔订单 | 同上 | `4` | 兼容全结清；正常业务以后端不返回上一笔为准 |

## 2. 总流程与入口矩阵

### 2.1 总流程

```text
03 首页普通申请
  → 03 完成公共门禁
  → 预览（产品 ID + 入口金额，无预订单 ID）
  → 成功缓存完整预览
  → 06 借款确认

03 自动提单卡（倒计时未结束）
  → 预览（产品 ID + 预单金额 + 预订单 ID）
  → 成功缓存完整预览
  → 06 借款确认

04 授信成功交棒 / 确认页内存数据丢失
  → 06 用产品 ID + 入口金额拉预览
  → 成功进入确认态；失败回首页根

确认页
  → 拉我的银行卡
  → 用户确认 / 自动倒计时结束
  → 下单
  → 处理中 | 失败 | 回首页
```

### 2.2 入口矩阵

| ID | 来源 | 必带路由职责参数 | 预订单 ID | 预览来源 | 失败 |
|----|------|------------------|-----------|----------|------|
| `L-ENTRY-HOME` | 03 首页-已获额/虚拟首页已绑卡申请 | 产品 ID、入口金额 | 空 | 03 已缓存；缺失时 06 补拉 | 参数/预览失败回首页根 |
| `L-ENTRY-AUTO-CARD` | 03 自动提单卡，倒计时未结束 | 产品 ID、预单金额、预订单 ID | 非空 | 03 已缓存；缺失时 06 补拉且带 ID | 回首页 |
| `L-ENTRY-CREDIT` | 04 授信绑卡成功、授信处理中轮询成功、证件 OCR 重拍后刷新授信成功 | 产品 ID、可借金额 | 空 | 06 必须拉预览 | 回首页根 |
| `L-ENTRY-RESTORE` | 进程重建后恢复确认路由 | 路由中产品 ID、入口金额、可选预订单 ID | 原值 | 06 重新拉预览 | 回首页根 |

参数有效性：

- 产品 ID：非空字符串；空则不请求预览，Toast/页面提示后回首页根。
- 入口金额：非空且可按本包金额协议解析为大于 `0`；无效则不请求预览，回首页根。
- 预订单 ID：只有自动提单卡入口带；普通路径固定空。
- 内存预览只在当前业务进程内交接，不写 SP/DataStore；页面取走后可清，避免下次借款误用旧订单。

### 2.3 直接进入结果页

| 来源 | 条件 | 去向 | 是否调预览/下单 |
|------|------|------|----------------|
| 03 自动提单卡 | 首页倒计时已结束 | 打款处理中 | 都不调 |
| 03 上一笔订单 | `o_orderStatus=0` | 打款处理中 | 都不调 |
| 03 上一笔订单 | `o_orderStatus=1` | 打款失败 | 都不调；携带 03 的 `o_failureReason` |

## 3. 借款预览

### 3.1 请求时机

- 03 已预览成功：确认页不重复请求，直接进入 §4 初始化。
- 没有可消费的预览：确认页首次进入只请求一次。
- 页面重组、生命周期恢复、银行卡列表刷新不得重复触发预览。
- 本模块无下拉刷新；不得暴露“刷新预览”按钮。
- 请求期间全局 Loading，返回前禁止重复请求和提交。

### 3.2 请求 `POST ori: /loan/pre/info`

| 字段 | JSON / 文档类型 | 客户端职责类型 | 普通申请 | 自动提单卡 | 来源与规则 |
|-------------------|-----------------|----------------|----------|------------|------------|
| `o_userId` | string | String | 必传 | 必传 | 当前会话 userId；不得用页面缓存旧用户 |
| `o_loanAmount` | string/number | String | 必传 | 必传 | 入口金额原始协议字符串 |
| `o_productId` | string/number | String | 必传 | 必传 | 入口产品 ID |
| `o_userCouponId` | string? | null | 不传/null | 不传/null | 本包无优惠券 |
| `o_stageFlag` | string/number | String | `"0"` | `"0"` | 固定预览阶段；本包 API 若定义不同先确认 |
| `o_orderId` | string? | String? | null | 必传 | 自动提单卡预订单 ID |

不得加的字段：

- 银行卡 ID：本链预览不传。
- 自动放款状态：由服务端预览返回，不由客户端预先决定。
- 优惠券 ID：固定 null。
- 预提交标记、复借标记：本包无该功能。

### 3.3 响应壳

- 成功：全局成功码 + `data != null`。
- 业务成功但 `data == null`：按预览失败。
- 失败：清本次内存预览，关闭确认页并回首页根；Toast 使用服务端 message，空则全局通用失败。
- 成功后保存为**页面会话态**，不要持久化。

## 4. 确认页初始化与页面状态

### 4.1 初始化顺序

1. 校验入口产品 ID、入口金额。
2. 尝试消费与当前入口匹配的内存预览。
3. 命中：灌入页面状态；未命中：调用 §3 预览。
4. 预览成功后同时：
   - 设置自动提单状态与倒计时；
   - 调 `ori: /bankcard/list`；
   - 按预览默认卡 ID 选卡。
5. 页面数据可见后允许用户操作。

内存预览必须核对至少产品 ID、入口金额、可选预订单 ID；不匹配则丢弃并重拉，禁止跨订单串数据。

### 4.2 页面状态

| 状态 | 页面 |
|------|------|
| 初始/预览加载 | 全局 Loading；确认内容不可提交 |
| 预览失败 | Toast 后回首页根 |
| 预览成功、卡列表加载中 | 可显示金额/计划；账户区域加载；提交禁用 |
| 可手动提交 | 金额/计划就绪；按钮可点，点击时再校验卡/密码 |
| 自动提单进行中 | 显示自动倒计时、取消入口；到点自动提交 |
| 自动提单已取消 | 转手动模式；取消入口消失 |
| 正在提交 | 主按钮与倒计时自动触发共用一把提交锁 |

### 4.3 返回

- 标题返回和系统返回完全同逻辑。
- 自动提单进行中：弹 `L-DIALOG-AUTO-EXIT`，不得直接离页。
  - 关闭：留确认页，倒计时继续。
  - 确认退出：离开确认页；**不自动调用取消自动提单接口**，服务端自动流程仍可能继续。
- 非自动进行中：调 `ori: /help/abandon/check`，页面职责值见 §10.8。
  - 后台要求选择原因：显示 `L-DIALOG-ABANDON`。
  - 不要求：直接返回。
  - 检查失败：留当前页；用户再次返回可重试。
- 放弃原因提交成功：关闭弹层并返回；关闭弹层不返回。

## 6. 收款账户

### 6.1 卡列表接口

确认页调用 `POST ori: /bankcard/list`。请求、列表项消费字段、`data=null` 不清空等解析规则以 [`05-绑卡.md`](./05-绑卡.md) §4 为准，本节不另维护第二套字段表。请求：

| 字段 | 类型 | 值 |
|------|------|----|
| `o_userId` | String | 当前会话 userId |

响应是当前用户银行卡数组。列表项至少消费：

| 字段 | 类型 | 用途 |
|-------------------|------|------|
| `o_bankCardId` | String? | 选中、下单、自动换绑；空卡不可选 |

| `o_accountTypeName` | String? | 账户类型展示名 |
| `o_icon` | String? | 图标；加载失败不影响选择 |

### 6.2 默认选中

1. 若预览 `o_bankCardId` 非空且列表有同 ID，选它。
2. 否则选列表第一张有效卡。
3. 空列表或没有有效 ID：不选中。
4. 刷新列表时，优先保留当前选中 ID；找不到再执行 1～3。

### 6.3 选择账户

- 点击 `L-SELECT-BANK` 打开 `L-DIALOG-BANK-LIST`。卡行用 05 §8 **选择模式**（有选中、无删除）。
- 单选；关闭不改当前选择。
- 手动模式选择后只更新本地页面。
- 自动提单进行中选择不同卡：
  1. 不先改本地选中；
  2. 调 `ori: /ignore/loan/apply/bind/bankcard`，请求订单 ID + 新卡 ID；
  3. 成功才替换选中卡；
  4. 失败保留旧卡并显示服务端 message。
- 自动进行中再次点当前卡：可直接关闭弹层，不重复请求换绑。

### 6.4 新增账户

- 银行卡弹层里的“新增”打开借款宿主新增账户弹层。
- 表单、过滤、校验、接口严格复用 `绑卡表单共用.md`，本文不复制。

- 绑定成功：
  1. 关闭新增弹层；
  2. 重新拉银行卡列表；
  3. 按 §6.2 选中。因绑定响应没有可靠新卡 ID，不保证自动选中新卡。
- 绑定失败：留新增弹层。

### 6.5 空卡提交

- 没有选中有效卡时，点击提交只在收款账户字段显示 `L-ERR-BANK-REQUIRED`。
- 不弹交易密码、不调下单。
- 自动倒计时到点但无卡：同样拦截下单并显示账户错误；自动状态记为“倒计时已结束”，**不自动重试**。用户加卡后须手动提交。

## 8. 交易密码与提交门禁

### 8.1 关键数据完整性

发起下单前必须具备：

- 当前会话 userId 非空；
- 预览订单 ID 非空；
- 入口产品 ID 非空；
- 入口金额有效；
- 收款卡 ID 非空。

缺任一项：

- 卡 ID 按 §6.5 字段错误；
- 其它关键数据按页面已失效处理：不下单，提示通用失败并回首页刷新。

还款计划为空、展示金额为空不由客户端阻止下单；这些由预览服务端负责。客户端不得据此重算或修补。

### 8.2 密码门禁

| `o_traderPwd` | `o_hasTransPwd` | 模式 | 行为 |
|---------------|-----------------|------|------|
| 非 true | 任意 | 手动 | 不弹密码，密码传 null |
| true | `"0"` | 手动 | 弹首次设置交易密码 |
| true | 非 `"0"` / null | 手动 | 弹校验交易密码 |
| 任意 | 任意 | 自动倒计时 | 跳过密码，传 null |

### 8.3 首次设置

- 交易密码长度：`00` 的 4 位。
- 输入、确认、格式校验和 RSA 公钥来源按账户安全共用能力；本模块只接成功回调。
- 设置成功后保留本次明文 4 位于**页面内存**，关闭弹层，再继续原提交。
- 用户关闭：留确认页，不提交。
- 设置失败：留弹层/确认页，按接口 message；不得当作已设置。

### 8.4 校验

- 校验请求至少带预览订单 ID + 交易密码（按接口要求加密）。
- 校验成功：页面内存保留本次密码，关闭弹层并继续提交。
- 校验失败：留弹层，清本次密码输入，显示服务端 message。
- 用户关闭：留确认页，不提交。

### 8.5 密码生命周期

- 只保留在确认页进程内存。
- 页面离开、下单完成或用户切换时立即清空。
- 禁止日志、埋点、SavedState、持久化或崩溃信息记录明文/密文。

## 9. 自动提单

### 9.1 开启判定

| 响应 | 状态 |
|------|------|
| `o_autoLoanStatus == 1` | 自动提单进行中 |
| 其它/null | 未开启 |

剩余秒：

- `o_autoLoanRemainTime` 空/负数 → `0`。
- 正数 → 以秒倒计时，每秒更新。
- 页面销毁取消本地 Job；页面重建必须重新请求预览取得服务端剩余值，不使用旧 SavedState 续算。

### 9.2 自动进行中 UI

- 显示自动提单说明和 `mm:ss`。
- 显示 `L-LINK-AUTO-CANCEL`。
- **隐藏** §9.6 申请时效提示倒计时（含稿面「99%」类装饰倒计时）；自动态只保留自动提单那一条计时，不得两条并排。
- 页面主按钮仍可手动触发 §8 门禁；手动点击时 `o_autoLoanStatus` 的提交值仍为当前本地模式：
  - 尚未到点、尚未取消：按手动触发处理，值 `0`，需要密码（按 §8）；
  - 倒计时到点触发：值 `1`，免密码。
- 返回按 §4.3 专用退出确认。

### 9.3 到点

1. 本地状态改为倒计时结束，保证只触发一次。
2. 获取提交锁。
3. 校验关键数据和卡。
4. 跳过密码；下单 `o_autoLoanStatus=1`。
5. 请求失败：留确认页，不自动无限重试；用户可手动重试，此时仍按自动值 `1`，直到取消成功或页面离开。

### 9.4 取消

- 点取消先出 `L-DIALOG-AUTO-CANCEL`。
- 关闭：继续倒计时。
- 确认：调用 `POST ori: /loan/cancel/auto`。

请求：

| 字段 | 类型 | 值 |
|------|------|----|
| `o_orderId` | String | 预览订单 ID，必传 |

成功：

- 停止倒计时；
- 本地状态改为已取消/手动；
- 后续下单 `o_autoLoanStatus=0`；
- 密码按手动模式重新生效。

失败：保持自动进行中；倒计时继续，显示服务端 message。

### 9.5 自动进行中换卡

`POST ori: /ignore/loan/apply/bind/bankcard`

| 字段 | 类型 | 值 |
|------|------|----|
| `o_orderId` | String | 预览订单 ID |
| `o_bankCardId` | String | 用户新选卡 ID |

成功才切本地卡；失败保留旧卡。

### 9.6 非自动模式提示倒计时

未开启自动提单时，稿面可以有一条申请时效提示倒计时（常见初始 600 秒 / 稿面「99%」类装饰），但它：

- 只展示申请时效提示；
- 到点不提交、不关闭页面、不改变请求参数；
- 不参与业务门禁。

**与自动提单互斥：**

| 本地模式 | 申请时效提示倒计时（§9.6） | 自动提单倒计时（§9.1） |
|----------|----------------------------|------------------------|
| 自动进行中（`o_autoLoanStatus==1` 且未取消） | **必须隐藏** | 显示 |
| 手动 / 已取消自动 | 可按 UI 交付展示 | 不显示 |

是否展示、初始 600 秒及文案均属于 UI 交付项；可执行 UI 没有该区域则不实现。它不得与 §9.1 自动提单倒计时混为一条业务计时器。

### 10.1 下单请求

`POST ori: /loan/confirm`

|-------------------|------|------|

| `o_riskValue` | String/number? | 不使用 |
| `o_delayDaysTips` | String? | 不使用 |

### 10.4 状态导航

| `o_loanStatus` | 行为 |
|----------------|------|
| `-1` / `0` / `null` | 移除确认页，进入打款处理中 |
| `2` | 移除确认页，进入打款失败；不传服务端 reason |
| `1` | 关闭确认页并回首页；首页按 [`03-首页.md`](./03-首页.md) §7.1 栈顶规则刷新 |

## 11. 结果页

### 11.1 打款处理中

入口：

- 下单成功壳 `o_loanStatus ∈ {-1,0,null}`；
- 03 自动提单卡倒计时已结束；
- 03 上一笔订单 `o_orderStatus=0`。

页面：

- 显示“借款处理中”语义和银行到账延迟说明；最终文案按 UI。
- 可触发 §10.7 好评提示。
- 不查订单、不轮询、不倒计时自动返回。
- 主按钮/系统返回：回首页根；首页成为栈顶后按 03 §7.1 刷新。
- 页面恢复不重复弹好评：同一页面实例只请求/判断一次。

### 11.2 打款失败

入口：

- 下单成功壳 `o_loanStatus=2`；
- 03 上一笔订单 `o_orderStatus=1`；
- 借款历史失败入口（后续模块）。

页面：

- 路由参数失败原因非空：优先展示该参数。
- 路由参数为空：展示可执行 UI 的默认失败文案。
- **下单 `o_loanStatus=2` 时固定传空路由参数，忽略下单响应 `o_reason`**；因此该入口使用默认文案。
- 03 首页上一笔订单、后续借款历史若携带自己的失败原因，可按前两条展示。
- 返回/主按钮：回首页根并触发首页刷新。
- 无“重新提交原订单”；重新申请必须从首页重新走门禁和预览。

### 11.3 无成功页

- `o_loanStatus=1` 直接回首页。
- 禁止新增成功动画、成功弹层或成功路由。
- 首页刷新失败时仍按 03 保留旧数据/重试规则，不回到已关闭的确认页。

## 12. Loading、错误、生命周期与安全

### 12.1 Loading

| 操作 | Loading |
|------|---------|
| 预览 | 全局或页面阻断式；不可提交 |
| 卡列表 | 账户区域 Loading；首屏未有卡时提交禁用 |
| 下单 | 主按钮 Loading + 全局防重复锁 |
| 取消自动 | 弹层确认按钮 Loading；倒计时继续 |
| 自动换卡 | 选卡确认局部 Loading；旧卡保持 |
| 好评检查 | 静默 |
| 放弃原因检查/提交 | 共用弹层规则 |

任何阻断 Loading 必须在成功、业务失败、网络失败和取消时释放；不得永久遮挡。

### 12.2 错误归属

| 场景 | 行为 |
|------|------|
| 入口参数无效 | 不请求，回首页根 |
| 预览失败/data null | 清缓存，Toast，回首页根 |
| 卡列表失败 | 保留已有卡；无卡则账户为空，允许用户重试/添卡 |
| 密码设置/校验失败 | 留密码弹层 |
| 下单业务/网络失败 | 留确认页，释放锁 |
| 取消自动失败 | 保持自动态和倒计时 |
| 自动换卡失败 | 保留旧卡 |
| 好评检查失败 | 静默 |

### 12.3 生命周期

- 确认页退后台：本地倒计时可以暂停 UI 刷新；回前台必须根据单调时钟补算经过秒数，不能简单从旧秒数继续导致延长。
- 页面被系统回收再建：重新预览，以服务端剩余秒为准。
- 下单已发出时退后台：不要因回来重组重复提交；请求结果仍只处理一次。
- 离开确认页：取消预览、卡列表、倒计时等页面协程；下单若网络层不可取消，回调不得导航已销毁页面。

### 12.4 隐私与安全

- 交易密码不记日志、不埋点、不持久化。
- 银行账号埋点只记是否选择/卡 ID 是否存在，不记完整账号。
- 错误日志不得打印完整请求体。
- 金额、产品 ID、订单 ID 可按全局脱敏/日志级别记录，但 release 不输出业务明文调试日志。
