## 写法约定

1. 接口路径写作 `ori: /xxx`；实际 path 从 `00` §6 指定的本包 API 文档映射。

4. 可见文案、颜色、字重、尺寸以可执行阶段确认的 UI 为准。未确认前不得自编西语。

## 1. 关键定论与术语

### 1.1 不可猜的业务定论

1. 账户侧卡列表是独立整页，不是授信第 4 步，也不是借款确认页的一部分。
2. 进入本页必须已登录；未登录不得停留本页（由 03 Tab / 08 入口拦截进 02）。
3. 列表只调 `ori: /bankcard/list`，body 只上送当前会话 `o_userId`。不使用首页、授信刷新、借款预览里可能出现的卡数组。
4. **添卡按钮（含空态按钮）仅当进入本页时传入的 `o_creditStatus == 2`（授信成功）才展示。** 其它状态（含 `0/1/3/6/8/9`、空、未知）一律隐藏。删除入口不受此门禁限制。
5. 本页不另拉首页/授信接口刷新状态；以路由/入口传入的授信状态快照为准。08 必须在跳转前传入最近一次首页（或等价会话）里的 `o_creditStatus`。
6. 删卡无「至少留一张」限制；最后一张也可删，删完走空态。
7. 删卡请求只上送 `o_bankCardId`；不上送用户 ID 到 body（用户身份走公共头）。不走批量删除接口。
8. 绑定成功判定完全交给共用篇：`o_isBindSuccess == true` 才关弹层并刷新列表。布尔 false/空：留弹层，不刷新。
9. 列表响应 `data == null`：**不覆盖**当前内存列表（首次进入内存为空，因此仍显示空态）。`data` 为非 null 数组（含空数组）：清空后用该数组替换。
10. 账号展示用列表项上的账号字段，**客户端不再二次掩码或补全**；服务端给什么展示什么。图标加载失败不影响列表、删除、后续借款选卡。
11. 不落绑卡草稿。关闭新增弹层即丢弃未提交输入。
12. 本页返回：**直接 pop**，不查放弃原因，不用 pageId `017`（`017` 只属于授信绑卡整页）。
13. 08 个人中心文档**不得**再写卡列表、空态、删卡、添卡表单或这两支接口字段。

### 1.2 术语

| 术语 | 含义 |
|------|------|
| 授信成功 | 入口 `o_creditStatus == 2`，与 03/04 同一枚举 |
| 有效卡 | `o_bankCardId` 非空（trim 后长度 > 0） |
| 列表模式卡行 | 本页使用：可删、不可单选高亮 |
| 选择模式卡行 | 06 选卡弹层使用：可点选、不展示删除 |
| 新增弹层 | 本页或 06 打开的底部表单壳；内部 `BK-*` |

## 4. 卡列表接口与字段

确认页（06）与本页使用**同一** `POST ori: /bankcard/list`。字段以本节为账户侧权威表；06 §6.1 与本文对齐，实现时不得做两套解析。

### 4.1 请求

| 字段 | 类型 | 必填 | 取值 |
|--------------------|------|------|------|
| `o_userId` | String | 是 | 当前会话 userId；空则不得发请求，按未登录回 02 |

不传分页、不传 bindType、不传产品 ID、不传订单 ID。

公共头（语言、token、包名、业务线、国家码等）走工程统一拦截，本文不重复。

### 4.2 响应 `data`

`data` 为银行卡对象数组。本模块**至少消费**：

| 字段 | 类型 | 空时 | 本页用途 | 06 额外用途 |
|-------------------|------|------|----------|-------------|
| `o_bankCardId` | String? | `""` / null 视为无效卡 | 删除目标；列表 key | 选中、下单、换绑 |
| `o_bankName` | String? | 展示空串 | 卡行银行名 | 同左 |
| `o_accountNo` | String? | 展示空串 | 卡行主账号 | 同左 |
| `o_bankCode` | String? | 忽略 | 保留在模型中，本页不单独展示 | 卡信息 |
| `o_accountType` | String? | 不推断 | 不作为 AR 展示主文案 | 账户类型 key |
| `o_accountTypeName` | String? | 展示空串 | 卡行类型名（CBU/CVU/Alias 展示名以服务端为准） | 同左 |
| `o_icon` | String? | 占位 | 银行图标 URL | 同左 |

### 4.3 明确不读 / 不展示

即使本包 API schema 带下列字段，账户列表与 06 选卡也**不得**用来做本模块判定：

| o_xxx | 原因 |
|-------|------|
| `o_cciNumber` | AR 账户展示不是 CCI 主字段 |
| `o_email` | 与绑卡展示无关 |
| `o_bindType` | 不按「还款添加 / 绑卡添加」分 Tab |
| `o_transType` / `o_cardTransMessage` / `o_lastTriggerTime` | 不做交易状态条 |
| `o_defaultCheckFlag` | 本页无默认选中；06 默认卡用预览 `o_bankCardId`，不用本字段 |
| `bankAccountSource` / `bankAccountType` | COL/Bre-B；本包不做 |
| 证件号、持卡人姓名 | 参考列表响应不含；新增头从会话/授信资料注入，**不要**指望本接口回填 |

### 4.4 `o_accountNo` 与 schema 里的 `o_cardNo`

本包 API 文档若把展示账号映射为 `o_cardNo` 而不是 `o_accountNo`：实现时按 `00` 映射消费**展示账号那一个字段**，UI 仍叫「银行账户」，不要同时展示两个。不得把 CCI 拼到账号后面。

### 4.5 `o_accountType` 语义（易踩坑）

AR 绑卡表单字典 type=`43`，key：CBU=`1`、CVU=`2`、Alias=`3`（以本包字典为准）。列表项 `o_accountType` 按**字符串 key** 理解，与表单一致。

部分 API schema 把 `o_accountType` 写成数字「0 活期 / 1 储蓄 / …」。**那不是本包账户列表的展示字典。** 若联调发现列表返回 0/1/2 且与 CBU/CVU/Alias 对不上：停问使用者，禁止在客户端把 0/1/2 翻译成活期/储蓄，也禁止用 type `43` 本地反查硬编码西语。展示优先 `o_accountTypeName`。

### 4.6 加载结果处理

| `data` | 处理 |
|--------|------|
| 非 null 数组（0..n） | 替换内存列表；0 条 → 空态 |
| `null` | 不 `clear`；保留进入本次请求前的列表 |
| 接口业务失败 / 网络失败 | 不 `clear`；按全局错误提示；无历史数据则保持空态，允许用户返回或（若门禁允许）去新增 |
| 数组中夹无效卡（无 ID） | 仍展示该行（账号/银行名照常）；**删除按钮可展示但点确认后若 ID 空则不发删除请求**，按本地提示或禁用删除（见 §7.3） |

不在客户端按银行名/账号去重。

## 5. 列表展示与空态

### 5.1 有卡 `BC-LIST-CARDS`

每行使用 §8 列表模式。行间距、卡片分层（账号区 / 银行区）跟实现用 UI。

- 账号：`o_accountNo`（或映射后的展示账号），不做本地格式化分组，除非确认 UI 明确要求（确认前保持原文）。
- 类型名：`o_accountTypeName`。
- 银行名：`o_bankName`。
- 图标：`o_icon`；失败用空 `Box`/通用占位，见切图规则。

### 5.2 空态 `BC-EMPTY`

| 元素 | 规则 |
|------|------|
| 插画 | 占位，图层名见 §13.6 |
| 说明文案 | `BC-TEXT-EMPTY`，最终西语待 UI |
| `BC-BTN-ADD`（空态内） | 仅 `o_creditStatus == 2` 显示 |

未授信成功且无卡：只展示插画+说明，**没有**新增按钮。用户不能从本页绑第一张卡（第一张卡走 04 授信链）。

### 5.3 Loading

- 首次进入且内存无卡：全页/内容区 Loading，不闪空态再刷出卡片（若框架只能先空后填，允许一次替换，但不要把空态插画当成错误）。
- 已有卡时的刷新（新增/删除成功后）：可在列表上盖局部 Loading；刷新失败保留旧列表。
- 删除请求进行中：删除确认弹层主按钮进入 Loading/禁用，防止连点。

## 6. 新增账户弹层（宿主壳）

### 6.1 何时可打开

仅当 `o_creditStatus == 2` 且用户点击空态或有卡底栏的 `BC-BTN-ADD`。未展示按钮时不得用隐藏入口、调试手势打开。

### 6.2 壳（相对 04）

| 项 | 本页 `BC-DIALOG-ADD` | 04 授信绑卡 |
|----|----------------------|-------------|
| 形态 | 底部弹层 | 整页 |
| 进度 | 无 | `4/4` |
| 顶栏黄条 | 无 | 有 |
| 关闭 | 点遮罩/关闭按钮丢弃输入 | 返回走放弃 `017` |
| 成功 | 关弹层 + §4 重拉列表 | 刷新授信并分流 |
| 主按钮西语 | 宿主 UI 自定 | 可与弹层不同 |
| 表单 | 共用篇 | 共用篇 |

`dismiss` 策略：关闭即销毁表单状态。不与 04 共用 View 状态。06 借款页新增弹层壳与本页同类，但成功后的选中规则仍只写在 06。

### 6.3 只读头注入

传给共用 `BK-TEXT-HOLDER` / `BK-TEXT-DNI`：

| 值 | 来源 |
|----|------|
| 姓名 | 当前会话展示名；空则让共用回退规则处理 |
| 证件号 | 当前会话已掩码证件号；空则共用回退 |

本页**不要**为填头去调列表或授信刷新。06 另有「优先授信展示资料」的规则，不要抄到 05。

### 6.4 成功 / 失败

1. 校验与 `ori: /bankcard/bind` 字段见共用篇。仍 **不送** `o_bankId`。
2. 成功：`onBindSuccess` → 关 `BC-DIALOG-ADD` → `getList()`。
3. 因绑定响应通常不带回新卡 ID：刷新后不保证新卡在第一位，本页也不做「滚到新卡」。
4. 失败：留弹层；列表不改。

进入弹层时拉银行列表：按共用篇（可全量一次，按类型过滤）。账户类型字典 type=`43`，点开类型选择再拉（共用篇）。

## 7. 删除银行卡

### 7.1 交互

1. 列表模式卡行点 `BC-LINK-DELETE`。
2. 记下该行 `o_bankCardId`（待删快照），打开 `BC-DIALOG-DELETE`。
3. 弹层：标题 + 说明 + 取消 + 确认。无顶栏关闭按钮时，取消 = 关闭。点遮罩是否关闭跟实现用 UI；关闭均不删除。
4. 确认 → `POST ori: /bankcard/delete`。
5. 成功：关弹层、清空待删快照、重拉列表。
6. 失败：留弹层或关弹层但保留列表（二选一以 UI 为准，**默认关弹层并 Toast 服务端 message、保留旧列表**）；待删快照可清。用户可再次点删除重试。

删除确认文案跟 UI。不因「这是默认收款卡 / 有在贷」在客户端拦截；拦截若发生，以删除接口失败 message 为准。

### 7.2 删除请求

| 字段 | 类型 | 取值 |
|--------------------|------|------|
| `o_bankCardId` | String | 待删快照 ID |

不传 `o_userId`、不传数组、不传 bankCode。本包 schema 若把同字段写成其它混淆名，仍按 `o_bankCardId` 映射。

响应：`data` 可为 void。成功以公共业务码为准（与全局「接口成功」一致），**不**再读 `o_isBindSuccess`。

### 7.3 无效 ID

待删 ID 为空：不打开弹层，或打开后确认为空操作（不发请求）。不要发 `o_bankCardId=""`。

### 7.4 并发

同一时刻只允许一个删除请求。列表刷新与删除不要叠成乱序覆盖：删除成功回调里发起的刷新，若晚于下一次手动进入请求，以较新请求的成功 `data` 为准（可用序号/job 取消）。

## 8. 卡行组件（列表 / 选择两模式）

同一套卡信息布局，用模式区分可点行为。06 选卡弹层应复用本职责，而不是再画一套字段绑定。

| | 列表模式（本页） | 选择模式（06 `L-DIALOG-BANK-LIST`） |
|--|------------------|-------------------------------------|
| 点击整卡 | 无 | 选中该项 |
| 选中勾 | 无 | 有；当前选中项高亮边框跟 UI |
| `BC-LINK-DELETE` | 有 | **无** |
| 空列表 | 走 `BC-EMPTY` | 由 06 决定空态是否露出新增 |

卡行绑定字段固定为 §4.2。比较选中用 `o_bankCardId` 相等，不要用对象引用或账号字符串。

## 10. API 总表

| 职责 | ori | 谁发起 | 请求要点 | 成功后 |
|------|-----|--------|----------|--------|
| 我的银行卡 | `ori: /bankcard/list` | 本页进入、新增成功、删除成功；06 确认页 | `o_userId` | 替换或保留列表见 §4.6 |
| 删除 | `ori: /bankcard/delete` | 本页确认删除 | `o_bankCardId` | 重拉列表 |
| 银行机构列表 | `ori: /bank/list` | 新增弹层（共用） | 见共用篇 | 按类型过滤 |
| 绑定 | `ori: /bankcard/bind` | 新增弹层（共用） | userId + 类型 key + 银行名 + bankCode + 账号 trim；不送 bankId | `o_isBindSuccess==true` 才回调宿主 |
| 账户类型字典 | `ori: /tools/dict` | 点开类型（共用） | type=`43` | 见共用篇 |

不调用：`ori: /bankcard/list/my`、`ori: /bankcard/list/all`、`ori: /bankcard/batch/delete`、`ori: /bankcard/bind/result`、`ori: /ignore/loan/apply/bind/bankcard`（后者仅 06 自动换绑）。

## 11. 返回、错误与登录失效

| 场景 | 行为 |
|------|------|
| 点返回 | pop；关弹层优先于 pop（若弹层开着，先关弹层） |
| 系统返回键 | 同左 |
| Token 失效 | 全局回 02；不要留空白列表页 |
| 无网 | 走工程无网提示；不清空已有卡 |
| 删除/列表业务错误 | Toast/全局错误 UI 用服务端 message；不改授信状态 |
| 新增校验失败 | 共用篇挂点，不关弹层 |
