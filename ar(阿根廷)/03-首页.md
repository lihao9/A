## 1. 首页术语与唯一判定

### 1.1 术语

| 文档术语 | 含义 |
|----------|------|
| 主按钮 | 页面上的主要行动按钮，如虚拟首页与首页-已获额的申请按钮（即 CTA） |
| 虚拟首页 | 宣传卡 + 主按钮 + 三步教程；没有真实产品选择器 |
| 首页-已获额 | **唯一一套**产品页：产品期限/期数选择 + 金额调节 + 申请按钮。账单卡、自动提单卡是同一页上的可选叠层，按数据显隐，**互不排斥、可同时出现** |
| 可用产品 | 至少一个产品 `o_isLock=false`（产品卡可操作） |
| 不可用产品 | `o_isLockAll=true`；产品与金额入口不可操作（仍是同一套首页-已获额） |

> 不要把「默认 / 有账单 / 有自动提单 / 产品锁定」写成互斥的多套首页。业务上只有 **虚拟首页 ↔ 首页-已获额** 二选一；首页-已获额内部由 `o_lastRecordLoan`、`o_preLoanInfo`、`o_isLockAll` 等字段决定卡片与锁定态。UI 登记表里的多行画板只是同一首页-已获额的不同稿面快照，便于对稿，不是独立页面状态机。

### 1.2 首页-已获额条件

以下条件必须同时满足：

1. 本地存在有效登录会话；
2. 首页响应 `o_ocrRetryType` 不是 `1`、`2`；
3. `o_isBindCard == 1`；
4. 满足以下任一：
   - `o_creditStatus == 2`（授信成功）；
   - 上一笔订单存在，且 `o_orderStatus` 为 `2` 或 `3`。

不满足任一条件，一律显示虚拟首页。

### 1.3 判定优先级

```text
无有效会话
  → 虚拟首页；不请求登录态首页接口

有会话
  → 请求首页信息
  → o_ocrRetryType ∈ {1,2}
      → 虚拟首页 + 按弹层顺序提示补拍
  → 已绑卡 && (授信成功 || 上一笔订单状态∈{2,3})
      → 首页-已获额
  → 其它
      → 虚拟首页
```

不得根据画板名另造状态；页面完全由上述业务字段决定。

### 1.4 结清约定

- `o_orderStatus=4` 是客户端兼容枚举。
- 正常业务中，订单全结清后后台不再返回 `o_lastRecordLoan`。
- 因此授信仍成功且已绑卡时仍进首页-已获额，只是不叠结清账单卡。
- 客户端不额外缓存旧账单，也不因本地旧数据继续展示已结清账单卡。

## 2. 页面骨架

### 2.1 主容器

1. 底部固定主 Tab 栏；**至少**包含「首页」「我的」两个入口。Tab 个数、顺序、文案、图标以实现阶段确认后的 UI 稿为准，不在正文写死。
2. 首次进入默认选中「首页」。
3. 允许点击 Tab 或左右手势横滑切 Tab；横滑不得抢占页内横向控件（如金额滑杆、期限横排）的手势，以不出现误切/卡顿为准。
4. 未登录点击「我的」：进入 02 手机号页，不切换到我的。
5. 已登录点击「我的」：切换到我的。
6. 页面内容避让系统状态栏、导航栏和底部 Tab。

### 2.2 首页公共顶栏

- 固定不随内容滚动。
- 左侧品牌标识；中间可展示欢迎语/脱敏账号；右侧客服入口 `H-ENTRY-SERVICE`。
- 点击客服进入 [`08-我的.md`](./08-我的.md) 联系我们页。
- 顶栏具体显隐、尺寸、文案以实现阶段确认后的 Figma 画板为准。

### 2.3 内容滚动

- 顶栏和底部 Tab 固定。
- 首页中间内容纵向滚动。
- 内容不足一屏时仍保持底部 Tab 在屏幕底部。
- 下拉刷新仅对首页内容生效。

## 3. 虚拟首页

### 3.1 适用状态

包括但不限于：

- 未登录；
- 已登录但未授信；
- 授信中、身份认证中、授信失败、身份认证失败；
- 基础信息已提交待 OCR；
- 已授信但未绑卡；
- 首页要求 OCR 补拍；
- 其它不满足 §1.2 的兜底状态。

### 3.2 内容

1. 宣传卡：欢迎标题、合规宣传说明、主按钮。
2. 三步教程：注册 → 获取额度 → 获取现金。
3. 不展示真实产品、金额范围或历史账单。
4. 未登录和已登录状态共用页面职责，但主按钮点击后的业务分支不同。

### 3.3 主按钮

元素 `H-BTN-APPLY`：宣传卡底部的唯一主按钮，功能是发起申请、继续授信流程。可见文案见 §14.4「最终文案」，正文不写死。

按钮点击顺序严格执行 §8；通过前置门禁后，根据 `o_creditStatus` 分流：

| `o_creditStatus` | 含义 | 后续 |
|------------------|------|------|
| `null` | 首页数据异常 | Toast 通用刷新重试提示；停留首页 |
| `0` | 未授信 | 按本地授信步骤进入首个未完成页面 |
| `1` | 授信中 | 若需 OCR 补拍则证件页；否则已绑卡进审核中页，未绑卡进绑卡 |
| `2` | 授信成功 | 若需 OCR 补拍则证件页；未绑卡进绑卡；已绑卡走借款预览 |
| `3` | 授信失败 | 授信失败结果页 |
| `6` | 身份认证中 | 与状态 1 相同 |
| `8` | 身份认证失败 | 清空本地身份表单缓存，进证件页重填 |
| `9` | 基础信息已提交 | 进证件页继续 OCR |
| 其它 | 未完成授信 | 按本地授信步骤进入首个未完成页面 |

本地授信步骤兜底：

| 缓存步骤 | OCR 开 | OCR 关 |
|----------|--------|--------|
| 0 | 工作信息 | 个人信息 |
| 1 | 工作信息 | 工作信息 |
| 2 | 紧急联系人 | 紧急联系人 |
| 3 | 证件页 | 绑卡页 |
| 其它 | 绑卡页 | 绑卡页 |

## 4. 首页-已获额

### 4.1 内容顺序

同一套首页-已获额，从上到下按数据叠层（不是互斥状态页）：

1. 上一笔账单卡（有 `o_lastRecordLoan` 才显示）；
2. 自动提单卡（有 `o_preLoanInfo` 才显示）；
3. 产品与金额卡（始终有；锁定态见 §4.4）；
4. 三步教程。

账单卡与自动提单卡**各自独立显隐，可同时存在**，均位于产品卡之前。无账单且无自动提单时，就是「只有产品卡」的首页-已获额，不是另一套页面。

### 4.2 产品默认选择

收到 `o_faceList` 后：

1. 优先选择列表中第一个 `o_isLock != true` 的产品；
2. 全部锁定时，选择 `o_loanRangeMax` 数值最大的产品用于只读展示；
3. 当前金额初始化为所选产品的 `o_loanRangeMax`；
4. 产品切换后，金额重置为新产品最大值并清空金额错误。

空列表或无法得到产品时：

- 不得发起借款预览；
- 申请按钮禁用；
- 不用默认空 productId 请求接口。

### 4.3 期限与期数

元素 `H-OPT-TERM`：产品卡顶部的横排期限选项，每项含期限与期数两行，选中态与未选中态样式不同。

- 期限：`o_productPeriodId` + 确认画板上的期限单位文案（对位后写入 §14.4）。
- 期数取 `o_installmentCountId`。
- 单复数规则（业务不变）：期数字符串为 `"1"` 用单数形，其它值用复数形；具体词形与大小写以确认画板为准，回填 §14.4，正文不写死示例句。

### 4.4 产品锁定

| 条件 | 行为 |
|------|------|
| 单产品 `o_isLock=true` | 该产品不可选，显示禁用态 |
| `o_isLockAll=true` | 金额增减、滑杆和申请按钮全部禁用 |
| 至少一个产品可用 | 只允许选择未锁产品 |

### 4.5 金额调节

元素：`H-BTN-AMOUNT-MINUS`（减）、`H-BTN-AMOUNT-PLUS`（加）、`H-SLIDER-AMOUNT`（滑杆，两端显示最小/最大值）。三者按位置与功能定位，均为图形元素，没有文案锚点。

字段：

- 最小值：产品内 `o_loanRangeMin`
- 最大值：产品内 `o_loanRangeMax`
- 步长：产品内 `o_loanRangeUnit`

规则：

1. `-`：当前值减步长；结果不得小于最小值。
2. `+`：当前值加步长；结果不得大于最大值。
3. 到边界后对应按钮禁用。
4. 金额字段按十进制数计算，展示按阿根廷货币格式化。
5. 空值/非法数字不得崩溃；按钮禁用并显示可理解错误。
6. 点击节流 500ms，避免连续修改。

### 4.6 申请按钮

元素 `H-BTN-APPLY`：与虚拟首页同一编号，位置同为主业务卡底部的唯一主按钮，功能是提交当前选中的产品与金额。可见文案见 §14.4；若确认稿上虚拟首页与首页-已获额两处文案不同，按各自画板回填，编号不拆。

通过 §8 门禁后：

1. 实时请求 OCR 开关；
2. `o_ocrRetryType ∈ {1,2}` → 进入证件补拍；
3. 否则请求 `ori: /loan/pre/info`；
4. 成功缓存**完整**借款预览响应，进入 [`06-借款.md`](./06-借款.md) 确认页并传产品 ID、金额；缓存只供当前入口一次消费，06 会核对产品/金额，不持久化；
5. 失败停留首页，按通用错误处理。

## 5. 上一笔账单卡

### 5.1 显隐

- `o_lastRecordLoan == null`：整卡不显示。
- 非空：显示订单时间/到期状态、订单金额、状态按钮。
- `o_orderStatus ∈ {2,3,4}`：显示还款进度。
- `o_planSimpleList` 非空：逐期显示摘要。
- **不**根据 `o_publicProcessingCount` 显示卡底「银行付款确认中」入口或角标（本包无此功能，见 §5.7）。

### 5.2 订单状态与点击去向

账单卡**整卡单击**（或稿面金额行右侧同一状态操作位，**只允许一个可点控件**）。随 `o_orderStatus` 改变文案；`2/3/4` 的跳转再按 §5.2.1 期数分流。实现时先在确认画板定位该操作位（见 §14.4 的 `H-BTN-ORDER-*`），再把可见文案回填「最终文案」；正文不写死按钮字。

| `o_orderStatus` | 状态 | 元素编号 | 点击去向 | 顶部时间/状态展示 |
|---|---|---|---|---|
| 0 | 打款中 | `H-BTN-ORDER-PAYING` | 打款处理中页 | 格式化 `o_orderTime`；文案/样式见确认画板 |
| 1 | 打款失败 | `H-BTN-ORDER-FAILED` | 打款失败页，传 `o_failureReason` | 格式化 `o_orderTime`；文案/样式见确认画板 |
| 2 | 正常待还 | `H-BTN-ORDER-DUE` | §5.2.1 | 见 §5.3 |
| 3 | 逾期待还 | `H-BTN-ORDER-OVERDUE` | §5.2.1（与待还同一套分流；**无**第二按钮） | 含逾期天数；文案格式见确认画板，回填 §14.4 |
| 4 | 已结清兼容值 | — | 确认稿若无此态，按 §1.4 不实现；若可点则仍走 §5.2.1 | 格式化 `o_orderTime` |
| null/其它 | 未知 | — | 按钮禁用兜底，不猜路由，提示刷新 | 格式化 `o_orderTime` |

首页不得自行发起还款申请/账单详情接口。路由细则见 07 §2。

#### 5.2.1 待还/逾期点击分流（单按钮）

仅 `o_orderStatus ∈ {2,3}`（以及确认稿允许点击的 `4`）适用。只传 `o_loanId`。

总期数取上一笔订单 `o_periodCount`（本包 wire 若只下发安装期数别名，在 `00` 映射到本槽；空/`null` 按 `0`）。

| 总期数 | 去向 |
|--------|------|
| `== 1`（单期） | [`07-还款.md`](./07-还款.md) **还款确认**；确认页自拉详情，应付基数=头 `o_loanLeftAmount`（整单剩余） |
| `!= 1`（多期或空） | [`07-还款.md`](./07-还款.md) **账单详情** |

本包**无续期**：不读 `o_extendApplyStatus`，不做「可续期则改走详情」分支（对照工程有续期时才会再分）。  
本包**无逾期双按钮**、无「银行付款」次入口。

### 5.3 今天、明天与普通待还

仅 `o_orderStatus=2` 时：

| `o_orderDueDays` | 判定（业务，不变） | 外观 |
|---|---|---|
| `-1` | 今天到期 | `H-STYLE-DUE-TODAY`，从确认画板取 |
| `-2` | 明天到期 | `H-STYLE-DUE-TOMORROW`，从确认画板取 |
| 其它 | 普通待还，格式化 `o_orderTime` | `H-STYLE-DUE-NORMAL`，从确认画板取 |

必须按以上实际协议值判断，不得擅自改为 `0/1`。

页面稿若只有普通待还与逾期画板、没有今天/明天到期单独画板：业务判定仍按上表，文案与样式在实现前用确认后的 UI 链接补，对不上就问使用者，禁止自编到期色/到期文案。

### 5.4 逾期展示

逾期与待还**同一套单点分流**（§5.2.1）。本节只约定逾期外观：

- 顶部含逾期天数；格式与文案见确认画板，回填 §14.4。
- 状态操作位元素为 `H-BTN-ORDER-OVERDUE`（单控件），样式取确认画板；**不要**做主/次双按钮行。

### 5.5 还款进度

- 来源：`o_repayPercent`。
- 仅状态 `2/3/4` 显示。
- 原始值范围为 `0f..1f`；UI 先限制到该范围，再按百分比展示（如 `0.25 → 25%`）。
- 不用计划条目数量自行推算覆盖服务端值。

### 5.6 分期摘要

`o_planSimpleList` 按服务端顺序展示，不排序。

| 字段 | 用途 |
|------|------|
| `o_periodStatus` | 单期状态：0 到期前未结清；1 到期日；2 逾期未结清；3 已结清 |
| `o_ctPeriod` | 当前期序号 |
| `o_installmentCount` | 总期数（摘要展示用；**点击分流看订单头 `o_periodCount`**，见 §5.2.1） |
| `o_totalOutstandingAmount` | 本期待还金额 |
| `o_dueTime` | 本期到期时间 |
| `o_prodTerm` | 客户端接收但首页摘要不读取 |

| `o_periodStatus` | 业务含义（不变） | 视觉变量 |
|---|---|---|
| 0 | 到期前未结清 | `H-STYLE-PERIOD-BEFORE` |
| 1 | 到期日未结清 | `H-STYLE-PERIOD-ON-DUE` |
| 2 | 逾期未结清 | `H-STYLE-PERIOD-OVERDUE` |
| 3 | 已结清 | `H-STYLE-PERIOD-CLEARED` |

### 5.7 银行付款确认中（本包不做）

**阿根廷本包无此功能。** 不实现账单卡底部「确认中」入口、数量角标，也不进 07 银行付款记录页。

## 7. 首页请求时机与刷新

### 7.1 何时请求

只认这一条，其它地方不要再列「从某某页返回再刷」：

- 未登录：不请求首页登录态接口，直接显示虚拟首页。
- 已登录、首页是导航栈顶、生命周期至少 `STARTED`、当前没有「禁止请求」门禁 → 请求首页。
- 因此会刷到的情况包括：第一次进首页、二级页（登录/合规/授信等）返回使首页重新成为栈顶、后台再进前台且首页仍是栈顶。同一套判定，不另写入口。
- 弹层/权限流程期间设置禁止请求，避免重复刷新覆盖当前交互；流程结束恢复。

### 7.2 首页请求

一次首页刷新同时：

1. 静默请求 `ori: /user/base/info`，更新本地展示名和脱敏证件号；
2. 请求 `ori: /main/base/info`，更新页面、菜单能力及弹层。

下拉刷新：

- 显示下拉刷新态，不再叠加全屏 Loading；
- 成功替换首页数据；
- 失败保留旧数据并结束刷新态；
- 不重复记首页首次曝光。

## 8. 主按钮 公共门禁

### 8.1 顺序

```text
点击首页主按钮
  1. 是否登录
     否 → 02 手机号页；结束
  2. 合规披露进度是否完成
     否 → 未授权引导 → 01 补走；结束
  3. ori:/report/v1/whether/report
     不需要上报 → 继续第 7 步
     需要上报 → 第 4 步
  4. 数据采集说明弹层
  5. 一次申请 READ_SMS + ACCESS_COARSE_LOCATION
     未全部授权 → 权限拒绝说明弹层 `H-DIALOG-PERM-DENIED` / 中止
  6. 上报进度弹层 → ori:/report/v1/record/report
     成功 → 第 7 步；失败/超时/关闭 → 中止
  7. ori:/credit/ocr_switch
  8. 按虚拟首页或首页-已获额职责分流
```

不得把 OCR 请求提前到登录、合规或上报门禁之前。

### 8.2 合规返回

- 用户完成补走后，自动重放刚才首页主按钮流程。
- 用户不同意：按 `01` 规则返回首页或登录页，不继续敏感操作。
- 重放时仍须重新判断当前首页类型，不能使用进入隐私页前的旧场景缓存。

### 8.3 上报

门禁：

- `o_isNeedReport != true`：直接继续。
- `o_isNeedReport == true`：弹说明 `H-DIALOG-REPORT-CONSENT` 并申请两项权限。
- “是否需要上报”接口失败：停止本次主按钮流程，不得按“不需要上报”放行。
- 两项权限必须全部授予才进入上报。
- 系统申请结果未全部授予（含只过一项、第一次拒绝、永久拒绝；不看 `shouldShowRequestPermissionRationale`）→ 弹出 **权限拒绝说明弹层** `H-DIALOG-PERM-DENIED`。关闭弹层：中止本次主按钮，**不上报**、不进 OCR。弹层主按钮：打开本应用系统设置页。从设置返回后重新检查两项；全开则继续进度弹层，仍缺则保持中止（不要再自动弹系统权限框）。外观与文案在可执行阶段按 §14 该弹层行回填，**本文不写 UI 链接**。
- 进度弹层 `H-DIALOG-REPORT-PROGRESS` 默认 35 秒（`00`）；不用 `o_reportTimeOut`。组包在弹层期间并行，超时或用户关闭则取消上送并停止本次主按钮。
- 上报成功后重新按当前首页类型继续；失败、超时、关闭均停止本次主按钮流程。
- OCR 开关接口失败：停止本次主按钮流程，不得使用旧开关继续授信或借款。

组包、风控词表、字段类型、XOR、`data` 见 [`风控上报共用.md`](./风控上报共用.md)。

## 9. 首页弹层顺序

### 9.1 首页信息成功后

严格串行：

```text
版本更新
  → 无更新/关闭弱更
  → OCR 补拍提示
  → 不需补拍/点击稍后
  → 应用内公告
```

不得同时叠多个首页弹层。

### 9.2 版本更新

`o_updateAppV1`：

| 值 | 行为 |
|---|---|
| 1 | 不弹 |
| 2 | 强制更新，不显示取消/关闭 |
| 3 | 非强制更新，可关闭；关闭后继续 OCR/公告链 |
| null/其它 | 不弹，继续后续链 |

### 9.3 OCR 补拍

首页响应 `o_ocrRetryType`：

- `1/2`：版本弹层之后显示补拍提示；
- “立即完善”：进入证件页并传补拍类型；
- “稍后”：关闭并继续公告；
- `0/null/其它`：不弹。

注意：页面弹层读首页响应；主按钮点击后的路由读本次 `ori: /credit/ocr_switch` 响应。两者不得混用旧值。

### 9.4 公告

- 请求 `ori: /notice/main`。
- `title` 或 `content` 任一非空才显示。
- 关闭后不触发其它首页业务。
- 公告失败静默，不阻塞首页。

## 11. Loading、错误与返回

### 11.1 Loading

- 首次已登录请求：首页全局 Loading。
- 下拉刷新：只显示下拉刷新指示。
- 用户基本信息、公告：静默。
- 主按钮链路接口：按钮防重复点击；请求期间不可重复提交。
- 全局 Loading 超时强制释放：秒数见 [`00`](./00-基础信息清单.md) §2「全局 Loading 强制释放」；从显示起算，到点必须关掉，不能永久遮挡页面。

### 11.2 首页接口失败

- 有旧数据：保留旧页面。
- 无旧数据：保持虚拟首页/可重试空态，不构造产品。
- 下拉刷新必须结束刷新动画。
- Token 失效按 02 回登录。
- 检测到无网络时可显示统一无网弹层；点击“刷新”重新请求首页。

### 11.3 返回

- 首页为主栈根页面时，系统返回按 App 统一退出策略。
- 弹层显示时优先处理弹层关闭规则；强更不可返回关闭。
- 底部 Tab 切换不产生重复主页面实例。

### 14.2 Agent 实现前检查

链接为空时严格执行 [`UI链接扫描规则.md`](./UI链接扫描规则.md)：

1. 请求使用者提供 Figma 整项目链接；
2. 自动扫描页面级 Frame；
3. 输出“职责 ↔ 画板名/node-id/置信度”；
4. 使用者确认后才填入 §14.3 并开始 UI；
5. 低置信度和代码/UI 状态不一致项禁止猜填；
6. 画板对完后，再按 §14.4 逐个元素对位：**按功能和位置找元素，不按文案找**；
7. 元素对位后把稿上实际文案回填 §14.4 的「最终文案」列；不得把未确认的对照稿文案写进正文；
8. 再按 §14.5 从同一套确认画板取样色值/字重/按钮样式，回填「最终样式」；换 UI 链接只改 §14.4 / §14.5，不改 §5 的状态码；
9. 页面稿上找不到对应元素或视觉变量，或出现本文没有的新元素，一律停下来问使用者，不自行增删功能、不自行配色。
