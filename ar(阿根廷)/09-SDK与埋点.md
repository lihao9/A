### 0.3 与 01 同意进度的关系

01 说「完全同意后再开**分析/采集类** SDK」——本版把这类定义为 **后续的 Analytics / Firebase**。

**AppsFlyer 冷启即 init+start**，不等待隐私进度 `2`。原因：安装归因窗口在首次打开，延后 start 会丢归因。若法务要求 AF 也必须同意后才 start：停问改本文，不得既冷启又再 start 一次造成双初始化。

## 1. 关键定论

1. Dev Key 只来自 `00` 本包配置槽，不进文档正文、不进 git 明文示例。可用本包构建配置 / secrets，符号自定。
2. 顺序固定：init（Dev Key + **无业务归因监听**）→（DEBUG 才开 AF debug log）→ start → 取 UID。
3. init / start 失败：记错误（无 key 内容），**不崩**；UID 走回退。
4. UID 读取：本端 SDK 提供的 UID API。非空才写入持久化槽。空串不写槽。
5. 对业务暴露的「AF ID」= 槽内非空 UID；否则回退 `00` 本包统一设备 id。回退值**不要**当成 UID 写入 AF 槽，以免以后 SDK 有值却读到设备 id。
6. 重试：第一次立即取；仍空则做**短间隔重试**（间隔与次数实现自定，合理即可；禁止长时间轮询或无限重试）。停止后仍空：保持槽空，业务读回退设备 id。
7. 登出/注销**不清** AF UID 槽（归因设备级）。
8. 公共请求头需要 `o_afId` 时填第 5 条的业务 AF ID。body 里 `o_appsflyerId` 同样。
9. `o_reqSubChannelAf`：本版首页继续 **null**（03 已定），AF SDK 不往这个字段写。
10. 禁止 Release 开 AF debug log。禁止日志打印完整 UID / Dev Key。

## 2. 初始化（进程）

在 **01 进程冷启**（与设备 id 生成同一轮）调用。入口跟壳：工程已有启动回调就用已有的，不要另开第二套。建议：先保证设备 id 槽有值，再 start AF（回退才有意义）。

伪流程（实现时换成自定符号与本端 SDK API）：

```text
进程冷启
  → 确保设备 id 槽
  → 本端 AF：init(本包 Dev Key, 无业务监听)
  → DEBUG: 开 AF debug log
  → start
  → 读 UID；空则短间隔少次重试，仍空保持槽空
  → 非空写入 AF UID 槽
```

不要在业务页（首页/登录页）里再 init。不要每次进首页 start。

广告 ID 相关权限：本版默认不加。若商店/AF 后台要求再加，停问后改本端清单。

### 2.1 本端附录（仅当壳尚未覆盖）

**Android 原生：** 官方 `com.appsflyer:af-android-sdk`；可在自定义 Application 启动回调里 init/start；UID 用 SDK 的 UID API；Release keep 只跟官方规则。Play `AD_ID` 默认不加。

**Flutter：** 用工程已接或本包选定的 AppsFlyer 插件，在 `main` / 插件要求的最早时机 init+start。广告 ID 按插件与商店要求停问。

其它端：用该端官方 AF SDK，职责与本节相同。

## 3. 持久化（先改 `00`）

`00` §8 槽名：**AppsFlyer UID**。

| 项 | 规则 |
|----|------|
| 值 | SDK UID 非空字符串 |
| 谁写 | 09 冷启成功读取时 |
| 谁读 | 公共头、02 注册、03 首页请求、风控组包、是否上报 |
| 清空 | 本版不清；换 Dev Key / 卸重装由系统与 SDK 决定 |

存储实现跟壳（系统偏好 / DataStore / 加密存储均可）；真实 key 字符串按本包风格自定一次，只对应 `00` 职责槽。
