## 写法约定

1. 接口路径写作 `ori: /xxx`；实际 path 从 `00` §6 指定的本包 API 文档映射。
2. 字段只写 `o_xxx`；真实 wire 从 `00` §6 本包 API 映射。禁止对照工程混淆字段。
3. 类名、分层、方法名、导航形状、存储 key 均由新工程自定（约定 §3）。
4. 状态码、显隐、校验、字段来源、去向是业务规则；文案、颜色、字重、间距是 UI 变量。
5. 本文出现的西语只允许出现在“当前稿快照/待确认文案”列；代码使用 §15 的最终文案，未确认不得自编。
6. `C-VAL-*` 是校验规则 ID，`C-INPUT-*` / `C-SELECT-*` 是字段职责 ID，`C-STYLE-*` 是视觉变量，不要求实现为同名 Kotlin 符号。绑卡表单用共用篇 `BK-*`，不要在 04 再编一套。

## 1. 不可猜的业务结论

1. OCR 开关来自 `ori: /credit/ocr_switch`，不能写死。
2. 首页进入授信前会拉一次；联系人本地校验通过后、聚合提交前必须再拉一次。
3. 本次开关结果同时决定聚合请求 `o_isNeedOcr` 和提交成功后的去向。
4. **业务只允许强开，不允许强关。** 中途变化只有：关保持关、开保持开、关→开。不为开→关设计回 PI 补身份、或把 Job 已填邮箱改回 PI 槽等补偿。二次拉取仍以当次接口值为准组装（与参考行为一致）；开→关视为后台违约场景，客户端不另做恢复页。
5. OCR 开：Job → 联系人 → 证件 → 绑卡；OCR 关：PI → Job → 联系人 → 绑卡。
6. OCR 开时邮箱、备用手机号、其它贷款在 Job；OCR 关时在 PI。不能两页同时提交。其它贷款在所在页必填。
7. DNI 必须恰好 8 位；7 位也是格式错误，不补 0、不提示补 0。
8. 本包不启用字典 type `33/34` 的手机号/姓名扩展正则。
9. 联系人支持通讯录选择和手动输入；两个入口进入同一校验。
10. 授信步骤与草稿按 userId 隔离；OCR 开关按 `00` §8 为全局槽。
11. **四类草稿同级必做（硬规则）**：PI / Job / 联系人 / **证件（身份表单草稿）** 均须按 `00` §8 持久化，不得只做内存态。杀进程、冷启后按 step + userId **必须能回填**（见 §3）。状态 `8` 只清证件草稿；其余草稿不因登出/授信成功主动清（§3.2）。
12. AR 证件页没有签发日：不展示、不校验、不提交。
13. 证件页 OCR 表单仅在正反面均上传成功后展示；未成功前不展示表单（见 §8.2）。
14. 证件/活体槽**已有成功 URL** 时：重传**进行中不先降级**；失败**不**覆盖成功态、不清已成功 URL（见 §8.3）；仅 Toast。
15. 证件正反面来源：相机 + 相册（点槽先出选择弹框）；活体页**禁止**相册（见 §8.3）。
16. 证件/活体上传前图片压缩默认口径：输出 **≤2MB**；**禁止在主线程（UI 线程）做压缩**（见 §8.3）；库选型跟工程。
17. 绑卡成功刷新授信，状态 `1` 和 `6` 都进入处理中。
18. `o_ocrRetryType ∈ {1,2}` 才是补拍；“OCR 开”与“需要补拍”不是同一概念。
19. 活体为独立页：前置摄像头、3 步 3 张；第一步固定正脸；后两步从眨眼/转头/张嘴随机取 2 个。人脸检测锁定 Google ML Kit Face Detection；预览取流跟工程壳，见 §8.6.7。活体图上传：**一次** `o_picType=3`，`o_base64String` 恰好 3 张且下标 0=正脸（见 §8.3 / §10.6）；**禁止**拆成 3 次各 1 张。

## 2. 流程与进度

### 2.1 OCR 关

```text
首页授信入口
  → PI 个人资料（1/4）
  → Job 工作/居住（2/4）
  → 两名联系人（3/4）
  → 再拉 OCR 开关
  → 若仍关：聚合提交（身份字段来自 PI）
  → 授信链绑卡（4/4）
  → 刷新授信结果
```

### 2.2 OCR 开

```text
首页授信入口
  → Job 工作/居住，含邮箱、备用手机号、其它贷款（1/4）
  → 两名联系人（2/4）
  → 再拉 OCR 开关
  → 若仍开：聚合提交（不带 PI 身份字段）
  → 证件/OCR/活体（3/4）
  → 授信链绑卡（4/4）
  → 刷新授信结果
```

### 2.3 联系人页中途强开

业务约定开关**只能强开**。本节是唯一允许的中途翻转。

用户可能按 OCR 关走完 PI，但联系人提交前后台把开关改成开：

1. 使用最新开关值；
2. 聚合提交 `o_isNeedOcr=true`；
3. 身份字段按 OCR 开规则不从 PI 带入；
4. 邮箱、备用手机号、其它贷款改取 Job 草稿；OCR 关进入 Job 时这三项通常未展示，因此允许为空；
5. 不返回 Job 补填，也不改取 PI 的邮箱/备用手机号/其它贷款；
6. 提交成功后进证件页，不进绑卡。

以上第 4～5 条按已确认的参考行为保留；后台必须能接受强开场景下 Job 邮箱/备用手机号/其它贷款为空。

### 2.4 进度文字

`1/4`～`4/4` 只是业务进度值；具体文案、进度条形状和颜色跟实现用 UI。

## 3. 本地步骤与草稿

所有职责槽复用 `00` §8，不另建平行 SP key。

> **证件草稿同级必做（硬规则）：** `00`「身份表单草稿」与 PI / Job / 联系人草稿**同为授信必做持久化**，不得因「先做拍摄/OCR 主链路」而只留内存、不落盘。内容至少含：OCR 表单字段、正反面/人像槽成功态、对应服务端 URL、本地可恢复预览路径（若有）、`o_applyId`（有则存）。活体检测页未完成路径**不**单独建草稿（§8.6 / §12.1）；活体已成功写入的三 URL 属于证件草稿一部分。

| step | 业务含义 | OCR 开恢复 | OCR 关恢复 |
|------|----------|------------|------------|
| `0` | 未推进 | Job | PI |
| `1` | PI 已完成 | Job | Job |
| `2` | Job 已完成 | 联系人 | 联系人 |
| `3` | 联系人已提交且进入证件 | 证件（**须回填证件草稿**） | 绑卡兜底 |
| `4+` | 已进入绑卡或之后 | 绑卡 | 绑卡 |

### 3.1 写入时机

| 时机 | 写入 |
|------|------|
| PI 确认成功 | PI 草稿；step=`1` |
| Job 下一步成功 | Job 草稿；step=`2` |
| 联系人离开/销毁 | 两名联系人草稿；剔除错误文案等 UI 临时态 |
| 聚合提交成功且 OCR 开 | step=`3` |
| 聚合提交成功且 OCR 关 | step=`4` |
| 证件页槽位/表单有成功进展（正反面上传成功、OCR 回填、活体三 URL 齐） | **及时写入**证件草稿（不必等整页提交） |
| 证件页主动返回 / 走放弃原因前 | **必须先**保存当前证件草稿（§12.1） |
| 首次证件影像提交成功 | 证件草稿；step=`4` |
| 重拍入口 | **不读取**旧证件草稿（内存与落盘均按空开） |
| 状态 `8` 从首页进入 | 清空证件草稿后进入首次证件流 |

杀进程 / 冷启：`step=3` 且非重拍入口 → 进证件页并**回填**该 userId 证件草稿（用例 44）。缺证件草稿读写实现 = **未完成 04**，不得标交付。

### 3.2 清理口径

- 按本次确认：不因登出、授信成功主动清 PI/Job/联系人/证件草稿/step（证件另见状态 `8` / 重拍）。
- 多用户靠 userId 隔离；实现不得使用未带用户维度的草稿 key。
- OCR 开关保持全局槽，不因切换用户自动清。
- 状态 `8` 只清证件草稿，不清其它草稿。

## 4. 表单校验公共规则

### 4.1 校验时机

1. 主按钮始终可点击；点击后校验当前页面所有**可见且适用**字段。
2. 本地错误一次计算完成，各字段同时展示；页面滚动并聚焦第一处错误。
3. 用户修改某字段，只重算与该字段直接相关的错误；其它字段错误不消失。
4. 本地校验存在错误时，不调邮箱/证件校验、OCR 开关、聚合提交等下一阶段接口。
5. 选择通讯录时可立即校验手机号；失败可以即时提示，但提交时仍必须重验。
6. `ori: /credit/email/validate` 失败：只 Toast 服务端 message（空则通用失败兜底），**不**按业务码分字段、**不**滚到某项。其它无法归属的接口失败走页面级/Toast，不清用户输入。

### 4.2 普通必填模板

> 三类错误边界见 [`特殊错误-UI定义.md`](./特殊错误-UI定义.md) §1～§2。

普通空值不为每个字段发明独立业务规则，统一两类：

| 模板 ID | 使用范围 | 错误语义 |
|---------|----------|----------|
| `C-ERR-REQUIRED-INPUT` | 文本、数字、手机号输入 | 请输入 |
| `C-ERR-REQUIRED-SELECT` | 字典、日期、地址选择 | 请选择 |

最终西语由 §15 确认。允许某字段覆盖模板，但业务代码不得用 placeholder 文案判断字段。

### 4.3 错误挂载

| 错误类型 | 默认展示 |
|----------|----------|
| 必填/格式/跨字段 | 对应字段下方内联 |
| 通讯录刚选入即不合法 | 对应联系人字段内联；可同时短提示 |
| 图片未上传（点反面/活体/提交时本地缺图） | **Toast**（先正后反门禁）；不进活体 / 不开反面拍摄 |
| 图片上传 / OCR / 活体上传接口失败 | Toast 服务端 message（空则通用失败兜底）。槽态**完整口径只认 §8.3**：仅**从未**上传成功的槽失败才可置 Failure；**已有成功 URL** 时重传进行中不降级、失败保持 Success / 原图 / 原 URL。只读本节不得自行把「可置失败态」扩到已成功槽 |
| 邮箱/证件校验接口失败 | Toast 服务端 message；不内联、不滚动 |
| 无法映射的其它接口失败 | Toast 或页面级通用错误，不清用户输入 |

颜色、红框、图标、字重全部取 §14.5，不在正文写死。

## 5. PI 个人资料（仅 OCR 关）

### 5.1 字段

| 元素 ID | 字段 | 必填 | 来源/上送 |
|---------|------|------|-----------|
| `C-INPUT-PI-FIRST-NAME` | 名 | 是 | 用户输入 → `o_firstName` |
| `C-INPUT-PI-LAST-NAME` | 姓 | 是 | 用户输入 → `o_lastName` |
| `C-SELECT-PI-GENDER` | 性别 | 是 | 字典 key → `o_gender` |
| `C-INPUT-PI-DNI` | DNI | 是 | 用户输入 → `o_idNumber` |
| `C-INPUT-PI-CUIL` | CUIL/CUIT | 是 | 用户输入 → `o_cuil` |
| `C-SELECT-PI-BIRTHDAY` | 出生日期 | 是 | 日期 → `o_birthdayStr` |
| `C-INPUT-PI-EMAIL` | 邮箱 | 是 | 用户输入 → `o_email` |
| `C-INPUT-PI-ALT-PHONE` | 备用手机号 | 否 | 有值才送 → `o_otherMobile` |
| `C-SELECT-PI-OTHER-LOANS` | 其它贷款 | 是 | 字典 key → `o_otherLoans`；**仅 OCR 关时本页展示** |

文档暂定顺序：其它贷款紧挨备用手机号后面。最终上下顺序以 §14 实现用 UI 为准，实现前按链接改本表，不在代码里写死稿面以外的顺序。

### 5.2 本地规则

| 规则 ID | 条件 | 错误语义 | 挂点 |
|---------|------|----------|------|
| `C-VAL-PI-FIRST-REQUIRED` | trim 后为空 | 普通输入必填 | first name |
| `C-VAL-PI-LAST-REQUIRED` | trim 后为空 | 普通输入必填 | last name |
| `C-VAL-PI-GENDER-REQUIRED` | 未选 key | 普通选择必填 | gender |
| `C-VAL-PI-DNI-REQUIRED` | 为空 | 普通输入必填 | DNI |
| `C-VAL-PI-DNI-LENGTH` | 非空且长度不等于 `8` | DNI 格式错误 | DNI |
| `C-VAL-PI-CUIL-REQUIRED` | 为空 | 普通输入必填 | CUIL |
| `C-VAL-PI-CUIL-LENGTH` | 非空且长度不等于 `11` | CUIL/CUIT 格式错误 | CUIL |
| `C-VAL-PI-BIRTHDAY-REQUIRED` | 未选有效日期 | 普通选择必填 | birthday |
| `C-VAL-PI-EMAIL-REQUIRED` | trim 后为空 | 普通输入必填 | email |
| `C-VAL-PI-EMAIL-FORMAT` | 不符合本包邮箱格式 | 邮箱格式错误 | email |
| `C-VAL-PI-ALT-PHONE-FORMAT` | 有值且不符合 `00` 手机号规则 | 备用手机号格式错误 | alt phone |
| `C-VAL-PI-ALT-PHONE-SELF` | 去区号后等于注册手机号 | 备用手机号不能与注册手机号相同 | alt phone |
| `C-VAL-PI-OTHER-LOANS-REQUIRED` | 未选 key | 普通选择必填 | other loans |

备用手机号为空合法。比较手机号前统一 trim、去空格/连字符、去 `+54`/`54`；比较和上送都使用标准化后的 10 位本地号。**输入框展示分组**与登录一致：AR **2-4-4**（[`00`](./00-基础信息清单.md) §2.1），空格不入库。其它贷款走普通选择必填，字典 type/key 见 §16。

### 5.3 服务端校验与确认

本地通过后调用 `ori: /credit/email/validate`，上送 userId、邮箱、DNI、CUIL、性别：

| 返回 | 处理 |
|------|------|
| 成功 | 展示 PI 信息确认弹层 |
| 失败 | Toast 服务端 message（空则通用失败兜底）；留在 PI；不进确认弹层；不挂字段、不滚动 |

不要在文档或代码里写死未确认的业务码，以本包 API 为准。确认弹层只核对，不再重新校验。确认后保存草稿、step=`1`、进入 Job。

| `C-SELECT-JOB-PAYDAY-1` | 发薪日 1 | 周期 key=`2` 或 `3` 时必填 |
| `C-SELECT-JOB-PAYDAY-2` | 发薪日 2 | 周期 key=`2` 时必填 |
| `C-SELECT-JOB-HOUSEHOLD-EXPENSE` | 家庭月支出 | 必填 |
| `C-INPUT-JOB-EMAIL` | 邮箱 | 仅 OCR 开时显示并必填 |
| `C-INPUT-JOB-ALT-PHONE` | 备用手机号 | 仅 OCR 开时显示；可选 |
| `C-SELECT-JOB-OTHER-LOANS` | 其它贷款 | **仅 OCR 开时显示并必填**；字典 key → `o_otherLoans` |

文档暂定顺序：OCR 开时其它贷款紧挨备用手机号后面（邮箱 → 备用手机号 → 其它贷款）。最终上下顺序以 §14 实现用 UI 为准。OCR 关时本页不展示、不校验、不从本页提交该槽。

### 6.2 地址

- 数据源为本包地址数据；业务层只要求“省 → 市”二级联动。
- 切换省必须清空市。
- 当前业务不展示第三级区，不提交有效 `o_addressDistrict`。
- 详细地址 trim 后上送，不自动拼接省市。
- 输入框 `maxLength=100` 限制长度；不另做超长校验、不挂超长错误文案。

### 6.3 无工作规则

职业字典 key=`"1"` 代表无工作。选择无工作时：

1. 隐藏并清空收入、工作年限、发薪周期、发薪日 1/2；
2. 上述字段不必填、不上送有效值；
3. 家庭月支出仍必填；
4. 切回有工作后重新要求填写，不恢复已清空旧值。

### 6.4 发薪规则

| 发薪周期 key | 展示与校验 |
|--------------|------------|
| `"2"` | 展示发薪日 1、2；两者均必选且日期不能相同 |
| `"3"` | 仅发薪日 1 必选；清空日 2 |
| 其它 | 不展示发薪日；清空日 1/2 |

双周时两个发薪日弹层（1～31 都展示，不从列表里删掉对端日期）：

1. **选中态只属于当前这一格正在编的发薪日。** 对端已经选中的那一天，在本弹层里不得画成选中样式（即使草稿里两格曾经相同，打开弹层时对端那天也按未选中画）。
2. 点对端已占用的那天：不进入选中态、不改当前格的待确认值。
3. 点确认时若待确认值仍与对端相同：不写入、不关弹层，提示两个发薪日不能相同（文案 §15）。
4. 提交仍作兜底：若两格仍相同，挂 `C-VAL-JOB-PAYDAY-DUPLICATE`（第二发薪日）。

选中/未选中的颜色、圆角跟实现用 UI，不在正文写死。

### 6.5 校验规则

所有普通必填使用 §4.2。特殊规则：

| 规则 ID | 条件 | 错误语义 | 挂点 |
|---------|------|----------|------|
| `C-VAL-JOB-PAYDAY-DUPLICATE` | 双周且两个发薪日相同 | 两个发薪日不能相同 | payday 2 |
| `C-VAL-JOB-EMAIL-FORMAT` | OCR 开且邮箱格式不合法 | 邮箱格式错误 | email |
| `C-VAL-JOB-ALT-PHONE-FORMAT` | OCR 开、备用号有值且格式非法 | 备用手机号格式错误 | alt phone |
| `C-VAL-JOB-ALT-PHONE-SELF` | OCR 开、备用号等于注册号 | 备用手机号不能与注册手机号相同 | alt phone |
| `C-VAL-JOB-OTHER-LOANS-REQUIRED` | OCR 开且未选 key | 普通选择必填 | other loans |

## 7. 紧急联系人

### 7.1 数量与输入方式

- 固定两名联系人。
- 每人字段：姓名、10 位本地手机号、关系。
- 支持系统通讯录选择，也支持手动输入。
- 通讯录返回后只做预填，不视为天然合法。
- 姓名允许编辑；手机号允许编辑；提交时统一重验。

### 7.2 标准化

1. 姓名 trim；不启用字典 type=34 扩展正则。
2. 手机去空格、短横线、括号、`+54`/`54` 前缀。
3. 标准化后必须符合 `00` 的 10 位规则。
4. 不启用字典 type=33 扩展手机号规则。

### 7.3 关系互斥

关系字典使用本包实际 key。参考业务约束：

- 直系亲属集合为 key `"1"`～`"5"`；
- 配偶 key=`"2"`；
- 两名联系人不能同时选择配偶；
- 当一人选择非直系关系时，另一人必须从直系集合选择；
- UI 打开关系选择器时过滤不可选项；提交时不二次校验关系组合。

如果本包字典 key 与上述不同，必须由 API 文档/字典配置映射语义，不得按显示文案判断。

### 7.4 校验规则

对联系人 1/2 分别应用：

| 规则 ID | 条件 | 错误语义 | 挂点 |
|---------|------|----------|------|
| `C-VAL-CONTACT-NAME-REQUIRED` | 姓名 trim 后为空 | 联系人姓名不能为空 | 对应姓名 |
| `C-VAL-CONTACT-PHONE-REQUIRED` | 手机为空 | 联系人手机号不能为空 | 对应手机 |
| `C-VAL-CONTACT-PHONE-FORMAT` | 标准化后非 10 位合法号 | 联系人手机号格式错误 | 对应手机 |
| `C-VAL-CONTACT-PHONE-SELF` | 等于注册手机号 | 联系人不能使用注册手机号 | 对应手机 |
| `C-VAL-CONTACT-PHONE-ALT` | 等于当前路径备用手机号 | 联系人不能使用备用手机号 | 对应手机 |
| `C-VAL-CONTACT-RELATION-REQUIRED` | 未选关系 | 普通选择必填 | 对应关系 |

跨联系人规则：

| 规则 ID | 条件 | 错误语义 | 挂点 |
|---------|------|----------|------|
| `C-VAL-CONTACT-PHONE-DUPLICATE` | 两人标准化手机号相同 | 两名联系人不能相同 | 联系人 2 手机 |

备用手机号来源：OCR 开取 Job 草稿；OCR 关取 PI 草稿。

### 7.5 提交

## 8. 证件、OCR 与活体

### 8.1 入口类型

| 入口 | `o_ocrRetryType` | 草稿 |
|------|------------------|------|
| 首次 OCR | `0`/null | 可读取证件草稿 |
| 补交/重拍 | `1` 或 `2` | 不读取旧证件草稿 |
| 状态 `8` 身份失败 | 按首次流 | 进入前清证件草稿 |
| 状态 `9` 继续 OCR | 按首次流 | 可读草稿 |

### 8.2 页面字段与表单显隐

姓名、姓氏、性别、DNI、CUIL/CUIT、生日由 OCR 回填后允许按 UI 编辑；字段本地规则复用 PI，但不包含邮箱、备用手机号。AR 不含签发日。

**OCR 表单区显隐（硬规则）：**

- 仅当 **正面、反面均为上传成功态** 时，才展示证件信息表单（及稿面若有的「请核对」类提示）。
- 任一面未成功（未拍 / 上传中 / 失败）：**不展示**表单整块；用户只能先完成正反面槽。
- 不因「仅本地有图、上传未成功」提前展开表单；以槽位成功态为准（与对照工程 `正反面均为成功态才出表单` 一致）。
- 人像/活体槽、底栏提交是否始终可见：以确认稿为准；业务上进入活体/提交仍受 §8.3 / §8.6.1 正反面成功门禁约束。

### 8.3 图片流程

1. **拍摄顺序（硬门禁）**：必须先正面上传成功，才允许拍/选反面；正反面均上传成功后，才展示表单，并才允许进人脸活体（见 §8.2 / §8.6.1）。  
   - 点反面槽但正面未成功：Toast「请先上传证件正面」类文案（§15），**不**开拍、**不**出相册选择、**不**挂槽内联错误。  
   - 点人像/活体或提交但缺正面或反面：同样 **Toast**，不进活体（见 §8.4）。
2. **正反面来源（硬规则）**：正面、反面均允许 **相机 + 相册**。点已允许的正/反面槽 → 先出 **来源选择弹框**（相机 / 相册，`C-DIALOG-ID-SOURCE`）；用户选定后再走对应权限与取图。活体页**禁止**相册，只走相机预览（§8.6）。
3. **压缩默认口径（硬规则）**：上传前压缩，输出体积 **≤2MB**（证件正反面与活体三张均适用）。达到该上限即可；边长/质量参数由实现按工程库调节，**不得**因未写边长而跳过体积上限。**禁止在主线程（UI 线程）执行压缩**（含 decode / 缩放 / 重编码写文件）；须在后台线程/协程完成，结束后再回主线程更新槽态并调上传。压缩后再调 `ori: /loan/pic/aws/upload`（入参见 §10.6），图片类型：正面 `1`、反面 `2`。  
   - **已成功面重传中不先降级（硬规则）**：该面若**已有**服务端成功 URL，用户再次选图/拍图后、压缩或上传**尚未结束**期间：槽位**继续 Success**，继续展示原成功图；**禁止**先改成 Empty / Uploading 空槽 / Failure，以免 OCR 表单闪收或误 Toast 缺图。  
   - **重传失败不覆盖成功态（硬规则）**：同上已有成功 URL 时，本次压缩/上传失败 → 只 Toast 服务端 message（或通用失败兜底）；**槽位保持 Success**，继续展示原成功图；**不**清该面 URL、**不**因失败把槽改成 Failure、**不**因此隐藏已展开的 OCR 表单。  
   - 该面**从未**上传成功：失败才可将该槽置 Failure；进行中可用上传中态。  
   - 重传**成功**：用新 URL/本地路径**覆盖**该面成功态，再按需触发 OCR。
4. 双面 URL 与 applyId 齐全后调用 `ori: /credit/idcard/ocr`（入参见 §10.8）。
5. OCR 非空字段覆盖当前表单；空字段不得覆盖用户已有值（回填字段白名单见 §10.8）。表单此时应已按 §8.2 可见。
6. 进入活体检测页的前置与流程见 §8.6。
7. **活体上传（硬规则）**：活体成功回传 **3** 张本地图后，按本条压缩口径压缩，再 **只调一次** `ori: /loan/pic/aws/upload`：`o_picType = 3`，`o_base64String` **恰好 3 个元素**（顺序见 §10.6 / §8.6.5）。**禁止**拆成 3 次请求、每次数组只放 1 张。  
   - 若三张活体 URL **此前已齐全**，本次重跑活体中途压缩/上传失败：Toast；**人像槽保持已成功态**，不清已成功的三张活体 URL（与正反面「重传失败不覆盖」同口径）；重跑进行中也不先把人像槽降为未成功。  
   - 若此前活体从未齐全：失败才可将人像槽置 Failure。
8. 证件页提交：正反面与活体三 URL 均成功后，再调邮箱/证件校验（只带 DNI），通过才出确认弹层。
9. 确认后调用 `ori: /credit/photo/upload`（入参见 §10.7），带上正反面 URL 与三张活体 URL 及表单字段。

### 8.4 证件页校验与提示

> 三类错误边界见 [`特殊错误-UI定义.md`](./特殊错误-UI定义.md) §1～§2。  
> **缺正/反面顺序门禁 Toast ≠ 特殊错误**（属「还没做完」本地缺态，不挂槽内联；专用西语仍见 §15.3b，**不**进特殊错误稿面内联清单）。

| 规则 ID | 触发 | 错误语义 | 挂点 | 归类 |
|---------|------|----------|------|------|
| `C-VAL-ID-FRONT-MISSING` | 点反面 / 点活体 / 提交，但正面未成功上传 | 请先上传证件正面 | **Toast** | 本地缺态门禁（非特殊错误） |
| `C-VAL-ID-BACK-MISSING` | 点活体 / 提交，但反面未成功上传（正面已成功） | 请先上传证件反面 | **Toast** | 本地缺态门禁（非特殊错误） |
| `C-VAL-ID-FORM-INCOMPLETE` | **仅**点人像/活体且表单不完整 | 请先完成证件信息（进活体前总提示） | **Toast** + 字段错误并滚到首错 | 本地缺态总提示（非特殊错误） |
| `C-VAL-ID-BIRTHDAY-INVALID` | 生日不是有效日期 | 出生日期无效 | birthday | **特殊错误** |
| `C-VAL-ID-CAMERA-DENIED` | 相机权限拒绝 | 出权限拒绝说明弹层；关闭则停在证件页、不进活体 | 弹层 | 权限门禁 |
| `C-VAL-ID-CAMERA-UNAVAILABLE` | 无前置摄像头或相机初始化失败 | 相机不可用 | 页级 Toast 或提示 | 见特殊错误表挂点（页级） |

> 主按钮**提交**且表单不完整：**不** Toast `C-VAL-ID-FORM-INCOMPLETE`；只挂各字段必填/格式错误并滚到首错（与对照工程一致）。

> **提交时活体未齐：不 Toast「请完成活体认证」。** 正反面 + 表单 + DNI 校验通过后，若三张活体 URL 未齐 → **直接进活体页**，不出确认弹层（与对照工程一致）。无 `C-VAL-ID-LIVENESS-MISSING` 文案 ID。  
> 活体回传张数异常属实现兜底，**不**单列产品 Toast/文案 ID（见 §8.6.3）。

图片上传、OCR、活体压缩/上传等**接口失败**：只 Toast 服务端 message（空则通用失败兜底）。槽态按 §8.3（含「重传中不先降级」「失败不覆盖成功态」）：**禁止**把「槽可置失败态」理解成一律盖掉已成功图。**不**另写专用错误文案 ID，**不**进 §15 特殊错误表。

服务端若返回“清正面/清反面/清活体”的明确业务码，按本包 API 码表清对应槽；码表未确认前不得臆造码值。

### 8.5 影像提交成功

| 场景 | 后续 |
|------|------|
| 首次 OCR | 保存证件草稿；step=`4`；进入绑卡 |
| 重拍 `1/2` | 清页面内存和证件草稿；刷新授信结果，按 §11.2 分流 |

### 8.6 人脸活体检测（业务，独立页）

证件页只做人像槽与上传；检测在**独立活体页**完成。预览与逐帧分析锁定 §8.6.7；不得缺步骤、少拍、改动作集合。业务侧封装用本工程命名与分层（约定 §3）。

#### 8.6.1 何时进入

| 入口 | 前置（全部满足才进活体页） |
|------|----------------------------|
| 点击证件页人像/活体区域 | 正反面均已上传成功；证件表单本地校验通过；`ori: /credit/email/validate` 只带 DNI 成功 |
| 证件页主按钮提交 | 同上；若三张活体 URL 尚未齐 → **直接进活体**（**不** Toast「请完成活体认证」），不出确认弹层；齐了才出确认弹层 |

前置失败：

- 缺正面/反面：`C-VAL-ID-FRONT-MISSING` / `C-VAL-ID-BACK-MISSING`，**Toast**（不挂证件槽内联），**不**进活体。
- 表单未完成（**点人像/活体**）：字段错误 + 滚到首错，并 Toast `C-ERR-ID-FORM-INCOMPLETE`（请先完成证件信息），**不**进活体。  
  （主按钮提交表单未齐：只字段错误+滚动，**无**此 Toast，见 §8.4。）
- DNI 校验接口失败：Toast 服务端 message，不进活体、不滚字段。
- 未授予相机权限：在证件页申请**本端相机权限**（不在启动链申请）。系统结果未授予（含第一次拒绝、永久拒绝）→ 弹出 **权限拒绝说明弹层** `C-DIALOG-PERM-DENIED`。关闭弹层：留在证件页、不进活体。弹层主按钮：打开本应用系统设置；从设置返回后已授予则进活体，仍未授予则继续留证件页。外观与文案可执行阶段按 §14 该弹层行回填，**本文不写 UI 链接**。
- 已授予：进入活体页。

#### 8.6.2 页面能力

- 使用**前置摄像头**预览。无前置摄像头或绑定失败：提示相机不可用，用户可返回证件页。
- 检测过程自动进行，用户不按快门。
- 底部展示 3 个反例示意（模糊不清、脸不完整、反光），文案与图从实现用 UI 取。
- 顶部引导文案随当前检测态切换，见 §15。
- 系统返回：未完成则不回传路径，证件页活体槽保持未完成。

#### 8.6.3 动作序列（3 步，3 张图）

固定 **3** 步，每通过一步截一张静帧：

1. **第一步固定为正脸**：人脸在取景范围内、朝向镜头，并连续稳定若干帧后通过。
2. **后两步**从以下三个动作中**随机取 2 个**（每次进入活体页重新抽，顺序打乱）：
   - 眨眼
   - 左右转头
   - 张嘴
3. 三步都通过且已截满 3 张后，把本地路径回传证件页并关闭活体页。

张数必须与步数一致。正常只在 3 步全过时回传 3 张；中途返回不回传。若实现收到不足 3 张或空路径：视为未完成——**不上传、人像槽不标成功**；**不**为此单独 Toast，**不**设专用文案 ID（非产品常规错误）。

#### 8.6.4 检测态（业务语义）

每一帧用 ML Kit `Face` 列表：无人脸 → `C-HINT-FACE-NONE`；多张时取 **boundingBox 面积最大** 的一张。

| 检测态 | 判定（用最大脸） | 是否推进步骤 |
|--------|------------------|--------------|
| 未检测到脸 | 列表空 | 否 |
| 未对准取景 | 框相对画面过小/过大，或框中心明显偏离取景 | 否 |
| 请正面 | 已入框但未正对镜头（yaw/pitch 超容差） | 否 |
| 请眨眼 / 请转头 / 请张嘴 | 当前随机动作未完成 | 否 |
| 张嘴但轮廓不足 | 上下唇轮廓点缺失，开口比为 0；文案可与「请张嘴」相同 | 否 |
| 当前步通过 | 见下表动作通过条件 | 是 |

动作通过条件（字段来自同一张 `Face`）：

| 步骤 | SDK 字段 | 通过条件 |
|------|----------|----------|
| 正脸 | `boundingBox`、`headEulerAngleY`、`headEulerAngleX` | 入框且朝向镜头，并连续稳定若干帧 |
| 眨眼 | `getLeftEyeOpenProbability` / `getRightEyeOpenProbability` | 先双眼开 → 再双眼闭 → 再双眼开（缺概率时按 1 处理，即偏「开」） |
| 左右转头 | `headEulerAngleY` | 同一次步骤内左右两侧都到过 |
| 张嘴 | `FaceContour.UPPER_LIP_BOTTOM` 与 `LOWER_LIP_TOP` | 唇间隙相对脸高超过实现阈值；无轮廓点则不开通、只提示张嘴 |

角度、开合概率、张嘴比、连帧数、脸框相对大小和中心范围 **不要写进本文**。口径：在能防呆拍的前提下 **略放宽**，真机好过检；实现放工程常量，联调可改。

步骤切换时清转头两侧标记和眨眼开合状态，避免上一步污染。

#### 8.6.5 回证件页之后

1. 压缩 3 张图（顺序与采集步一致：①正脸 → ②随机动作一 → ③随机动作二）；任一张压缩失败则整次活体失败：按 §8.3 第 7 点——此前活体 URL 已齐全则人像槽保持成功；否则人像槽失败。正反面一律保留。
2. **一次**调用 `ori: /loan/pic/aws/upload`：`o_picType = 3`，`o_base64String = [正脸, 动作一, 动作二]`（长度必须为 3，见 §10.6）。**禁止**三次各传一张。
3. 该次成功且 `o_pictureUrlList` 至少 3 条：按下标 0/1/2 写入三张活体 URL（覆盖旧活体 URL），人像槽标成功。条数不足按未完成（人像槽失败或保持原成功态，见 §8.3 第 7 点），**不**另写产品 Toast。
4. 上传失败：已成功的证件正反面 URL 不动；活体侧按 §8.3 第 7 点；无「清槽」业务码时**不要**清正反面。允许重进活体。
5. 重进活体必须重新跑完整 3 步，不得只补拍缺的一张。

#### 8.6.6 与影像提交

`ori: /credit/photo/upload` 必须带齐：证件正、反 URL + 活体三 URL。缺一不可出确认弹层、不可提交影像。

#### 8.6.7 检测能力与取流

活体页**必须**使用 Google ML Kit Face Detection 做人脸分析，不得换成其它人脸 SDK 或自研模型顶替检测。预览与取流**跟当前工程相机栈**（有壳用壳）。

| 层 | 口径 | 说明 |
|----|------|------|
| 预览与取流 | 跟壳 | 前置摄像头连续预览 + 逐帧分析。Android 原生且壳未定时：可用 CameraX `Preview` + `ImageAnalysis`、前置镜头。Flutter：本工程相机插件取帧再交给 ML Kit，不要在 Dart 里抄 CameraX API |
| 分析背压 | 实现建议 | 实时检测应避免积帧卡顿（只保留最新帧或等价策略） |
| 人脸检测 | 锁定 | Google ML Kit Face Detection，需能提供轮廓点与双眼开合概率。Android 原生未另定时可用 `com.google.mlkit:face-detection`（unbundled）；Flutter 用工程已接的 `google_mlkit_face_detection`（或同等官方插件） |
| 输入 | 跟壳 | 把与预览同一路的图像帧交给 ML Kit（旋转角与取流一致） |

检测器选项必须打开下列能力（否则眨眼/张嘴无法做；名称以 ML Kit 为准，各端绑定同一语义）：

| 选项 | 值 | 原因 |
|------|----|------|
| performanceMode | `PERFORMANCE_MODE_FAST` | 实时预览 |
| landmarkMode | `LANDMARK_MODE_NONE` | 本流程不用 landmark |
| contourMode | `CONTOUR_MODE_ALL` | 张嘴用唇轮廓 |
| classificationMode | `CLASSIFICATION_MODE_ALL` | 眨眼用开合概率 |
| tracking | 开启 | 连续帧稳定跟踪 |
| minFaceSize | 实现自定 | 过滤过小脸；略放宽，不必锁死具体值 |

约束：

- 同一活体页生命周期内复用一个检测器客户端；离开页面必须关闭检测器与相机会话，禁止泄漏。
- 分析回调未处理完时丢弃后续帧（单飞），避免并发改步骤状态。
- 截帧在当前步判定通过的那一帧取 JPEG，与预览同一路图像，不另开拍照用例凑数。
- ML Kit / 相机不可用时按 `C-VAL-ID-CAMERA-UNAVAILABLE` 处理，允许返回证件页重试。
- 证件正反面拍照仍可用工程既有相机/相册方案，**不必**走 ML Kit。

### 11.2 刷新授信

| 状态 | 后续 |
|------|------|
| `1` 或 `6` | 处理中 |
| `2` 且 productId、可借金额有效 | 关掉授信页，传产品 ID + 可借金额给 06；06 先请求预览 |
| `2` 但缺产品/金额 | 回首页并刷新 |
| `3` | 失败页 |
| 其它或请求失败 | 回首页根 |

### 11.3 处理中

- 总时长 30 秒。
- 每秒更新倒计时。
- 每 3 秒调用一次刷新授信。
- 同一时刻只允许一个刷新请求。
- 状态 `2/3` 提前结束；`1/6/9/其它` 继续等待。
- 30 秒结束仍未终态：回首页根并刷新。
- 页面返回：直接回首页，不弹放弃原因。

## 12. 返回、Loading 与错误

### 12.1 表单返回

活体检测页返回：直接关页回证件，不调放弃原因检查，不保存活体草稿。未完成则不回传路径。

PI、Job、联系人、证件、绑卡点击系统返回或标题返回时：

1. 保存对应草稿（证件**必须**按 §3 落盘，不得只改内存）；
2. 调放弃原因检查；
3. 服务端要求且列表非空 → 展示原因弹层；
4. 选择原因后提交；成功才返回；
5. 不要求 → 直接返回；
6. 检查接口失败：保持当前页，不返回、不另开退出入口；用户再次点击返回时重新检查。

页面职责 ID：PI=`006`、Job=`033`、联系人=`007`、绑卡=`017`。证件页放弃原因 pageId 候选 `013` 与接口说明 `008` 冲突，**实现前必须由本包 API 确认**。

### 12.2 Loading

- 下一步请求期间按钮防重复。
- 字典/地址首载可用页面 Loading；已有数据刷新不得清空选择。
- OCR 开关、聚合提交、影像提交、绑卡不可并发重复。
- 图片每个槽独立上传态；一个槽失败不清另一个槽。  
- **已成功槽重传**：进行中不先降级；失败只 Toast，槽保持 Success 与原图/原 URL；成功才覆盖（§8.3）。不得误写成「一选图就 Empty/Failure」或「失败一律置 Failure」。
- 页面销毁取消只属于该页的任务；处理中轮询必须停止。

### 12.3 错误

- 网络失败保留输入与草稿。
- 服务端 message 只用于对应字段或页面提示，不参与业务判断。
- Token 失效复用 02 全局清会话返回登录。
- 未知业务码不当成功处理。
