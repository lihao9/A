# 整包落地顺序（AR · 给一次性实现 agent）

> 和 [`AGENT实现约定.md`](./AGENT实现约定.md) 一起用。  
> **目标**：少返工、可验收。  
> **不是**：在一次对话里把整个 App 写完。

模块正文写的是「这一块做什么」；本文写「整包按什么顺序做、做到哪必须停」。

---

## 0. 不要一次会话吞全工程

原因（实现时必须当硬约束）：

1. 模块文档未写完（后续 Analytics/Firebase 扩写 09）时，禁止假装「埋点全套已交付」；**业务模块 00～08 + 09 AF 已齐**。  
2. `00` 里待填项（API 文档、H5、业务线、货币、RSA 公钥等）未齐时，禁止写网络层与上送加密。  
3. UI 链接表为空时，禁止写该模块布局和切图；全项目实现用 Figma 必须使用者确认一次总表。  
4. 单次上下文装不下 01～0N 全文 + 对稿取样；硬写会漏态、抄对照稿、模块互相打架。

允许的「一次性」：**一次只交付一个波次**（见 §2），该波次读约定 + `00` + **本波次模块**，做完跑该模块测试矩阵，再开下一波。

## 1. 开写代码前的总闸（全未通过则不准开工）

| # | 闸 | 谁填 | 不通过时 |
|---|----|------|----------|
| G1 | `00` §6 本包 API 文档路径已填 | 使用者 | 只搭无 wire 的壳，禁止臆造 path |
| G2 | `00` 货币、H5、业务线、马甲、RSA 公钥来源已填 | 使用者 | 禁止金额展示定稿、禁止隐私 WebView、禁止加密上送 |
| G3 | 本包 `applicationId` / 签名 / 根包名已定（防关联清单 §3） | 使用者 | 禁止当「可上架工程」交付 |
| G4 | **实现用** Figma 整文件链接已给，并完成全量画板总表确认 | 使用者确认 | 各模块 §UI 保持空表；本波次只做状态机/接口，或停 |
| G5 | 本波次涉及的模块文档状态为「已定稿」 | 梳理 agent | 未定稿模块整波次跳过，不得用其它目录未定稿文档顶上 |

总闸过了仍要按模块走扫描规则：总表确认 ≠ 已经填好每个元素的最终文案/色值；那是该波次里对稿的工作。

## 3. 「壳与跨模块」可以后补（默认不写专篇）

**梳理阶段优先写完业务模块（04～09），不要为了壳专篇停下来。** 网络库、DI、导航、UI 框架（Compose / Flutter / 其它）每人/每包可以不一样，业务文档禁止写成某一种脚手架。有现成工程时 **沿用该工程壳**，不要按本文再推断必须单 Activity 或 Compose。

跨模块只在**已有业务篇里用职责写清**，例如：

- 登录成功弹出认证栈、进首页；  
- token 失效回 02 手机号页；  
- 未登录点「我的」进 02，不切 Tab；  
- 危险权限只在 03 上报链 / 授信相机等正文规定的时机申请；  
- 首页账单卡只跳转还款职责，不自造还款接口。

实现阶段由**当时的实现者**按本工程已有风格自搭 W0（或沿用已有壳）。若实现者要求补一篇壳说明，再单开短文，且只写与本仓库一致的选型，仍不得回改业务判定。

## 4. 实现会话内的停问规则

下列情况 **停、列差异、等使用者**，不要为了「一次性做完」往下编：

- 实现用画板与模块正文的状态机冲突。  
- 元素编号在确认稿上找不到，或稿上多了正文没有的入口。  
- 视觉变量稿面未覆盖（如首页今天/明天到期）。  
- `00` 待填被业务代码真正用到。  
- 跳转到尚未定稿的模块：只留职责路由占位，禁止发明该模块页面规则。

## 5. 每波次收工

1. 该模块测试矩阵全跑（能跑的用测试/人工清单）。  
2. 元素表「最终文案」、视觉变量表「最终样式」已填。  
3. **字段/规则表对勾**（[`AGENT实现约定.md`](./AGENT实现约定.md) §12.7）：本波涉及的字段全表 / 采集规则表 / 测试要点表逐行标「已做 / 文档允许空 / 未做」。有「未做」则**禁止**写「完整版 / 齐了」；列清单或补完再收尾；禁止空数组冒充已采集。  
4. 防关联：本波次按 skill `code-layer-anti-association` 模式 B 出快评，综合分目标 ≤35。  
5. 在 `modules-index.md` 把该模块状态改为「已实现（待联调）」或使用者指定的状态。  
6. 下一波次只带上：约定 + `00` + 本波次文档 + 导航/会话已有实现的职责说明（不要把上一波次全文再贴进上下文）。

## 6. 和「文档一次性写完」的关系

| 工作 | 一次性？ |
|------|----------|
| 把 04～09 业务模块文档按约定写完 | **优先**。一篇一篇写，不和写代码混；不要求先有壳专篇 |
| 实现用 Figma 全量扫描总表 | 写代码前做一次确认即可 |
| 壳 / 框架选型 | **后补或实现者自定**，不写进业务判定 |
| 写代码 | **按 §2 波次**，每波次一次任务 |

梳理 agent 写 04～09 时仍执行 [`AGENT实现约定.md`](./AGENT实现约定.md) §11：业务写死、三张表留空、对照稿不算实现稿。05～09（AF）已定稿；Analytics/Firebase 不在本版。
