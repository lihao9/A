## 写法约定

1. 接口路径写作 `ori: /xxx`；实际 path 从 `00` §6 指定的本包 API 文档映射。
2. 字段只写 `o_xxx`；真实 wire 从 `00` §6 本包 API 映射。协议语义可保留。符号与分层按约定 §3。禁止对照工程混淆字段。
3. `RP-*` 只是文档职责 ID，不要求同名 Kotlin 符号。
4. 金额按字符串接收和透传；展示走本包金额格式化器。不得用渠道费率改账单金额。
5. 可见文案、颜色、字重以可执行 UI 为准。未确认前不得自编西语。
6. 已锁定：**无优惠券、无续期、无 Bre-B、无对公银行链 / 无上传凭证、无还款处理中页、无通道费、无 PIN/OTP 分期校验页、无银行付款确认中 / 无付款记录列表页**。

## 1. 关键定论与术语

### 1.1 不可猜的业务定论

1. 所有还款页都要有效 `o_loanId`。空则 Toast/提示后回首页根，不发请求。
2. 账单详情与还款确认都调 `ori: /bill/detail`，请求只带 `o_loanId`。不带续期比例、不带 AES `type`（除非本包 API 强制 App 必传，届时停问）。
3. 首页账单卡 `o_orderStatus ∈ {2,3}`：**整卡单点**；`o_periodCount == 1` 进还款确认，否则进账单详情（见 03 §5.2.1）。只传 `o_loanId`。本包无逾期双按钮、无续期分流。
4. 首页单期直达确认：确认页自己拉账单，应付金额用详情头 `o_loanLeftAmount`（整单剩余）；跳过详情勾选。
5. 从详情点「立即还款」：应付金额 = 当前勾选期次的 `o_loanLeftAmount` 之和（字符串金额按本包解析后相加，再格式化回协议字符串）。
6. 勾选规则见 §4.3：必须连续覆盖「第一笔未结清」到用户点中的那期；逾期期与第一笔未结清不能取消勾选。
7. 整单 `o_orderStatus == 4`（全结清）：隐藏立即还款，仍可进还款历史。
8. 还款渠道来自详情 `o_repaymentChannelList`。Tab 用 `o_channelTypeMsg` 去重保序，**不要**用西语文案判断是不是 DEBIN / QR / Transferencia（见 §6.2）。
9. DEBIN：`o_channelType` trim 后等于 `"4"`。
10. 固定账户 UI：`o_orderType` trim 后等于 `"1"`：展示账号并复制，**隐藏**「立即支付」，不调申请。
11. `o_channelType == "2"`：AR 后台**正常不返回**（无对公银行链）。若误下发：仍可进 Tab；**不**进 §10 页。`o_orderType=="1"` 走 §6.4；否则确认页申请走 §9。详见 §6.5。
12. 其它启用渠道：确认页申请；成功且 `o_redirectUrl` 非空 → 应用内 Web；URL 空则留确认页并提示服务端 message。
13. 申请上送的 `o_amount` **等于确认页输入金额**（按本包规则向下取整到整数串）；`o_checkLoanLeftAmount` 是进入确认页时的勾选/整单剩余。不减通道费，不传 `o_repaymentFee`。
14. `o_jumpSourceType = 1`（APP）。`o_repaymentStage` 固定 `"0"`。`o_renewRepaymentType` 固定 `"0"`。不传续期 true。
15. 线上 Web 关闭后仍停在还款确认，不自动再申请。
16. 不把 03 的 `o_orderStatus` 与 06 下单 `o_loanStatus` 混进还款申请结果判断。
17. 不实现上传凭证、不传凭证图/付款人/存款日期等字段；无还款处理中页。

### 1.2 术语

| 术语 | 含义 |
|------|------|
| 整单剩余 | 详情头 `o_loanLeftAmount` |
| 勾选剩余 | 勾选期次 `o_loanLeftAmount` 之和 |
| 输入金额 | 确认页用户改过的应付；默认等于基数 |
| 启用渠道 | `o_status != "1"` 且 `o_channelTypeMsg` 非空（**不**因 `o_channelType=3` 丢弃） |

## 4. 分期勾选

列表：`o_repaymentPlanList`，**服务端顺序**，不排序。

### 4.1 每期至少消费

| 字段 | 用途 |
|-----------|------|
| `o_ctPeriod` | 当前期；比较勾选范围 |
| `o_periodCount` | 总期数；展示 `当前/总` |
| `o_dueTime` | 本期到期 |
| `o_billAmount` | 本期账单应还（创建时固定值） |
| `o_repaymentAmount` | 本期已还 |
| `o_loanLeftAmount` | **勾选加总用这个** |
| `o_periodStatus` | 0 到期前未结清 / 1 到期日 / 2 逾期未结清 / 3 已结清 |
| `vterdueStaouRsef`（期次是否逾期） | 展示逾期天数/滞纳金时用；与 status=2 同时出现时都要能展示 |
| `o_dueDay` | 逾期天数 |
| `o_overdueFee` | 滞纳金 |

已结清：无勾选框，不可点选。未结清：有勾选框。

期次外观语义对齐 03 §5.6（`o_periodStatus`），样式取详情画板。

### 4.2 初始勾选

进入详情：所有期次本地 `selected=true`。已结清无框，加总时其 `o_loanLeftAmount` 按 0 或服务端原值加（正常为 0）。效果：未结清期默认全选。

### 4.3 切换勾选

记 `firstUncleared` = 第一个 `periodStatus != 3` 的下标。对点击的未结清期 `P`（其 `o_ctPeriod = N`）：

**选中 P（当前为未选 → 选）：** 所有未结清且 `o_ctPeriod <= N` 的期改为选中。

**取消 P（当前为选 → 未选）：**

- 若该下标 == `firstUncleared`：**不允许**，保持选中。
- 若该期逾期（`periodStatus==2` 或期次逾期布尔 true）：**不允许**取消。
- 否则：所有未结清且 `o_ctPeriod >= N` 的非逾期期改为未选；逾期期保持选中。

不要出现「只选第 3 期不选第 1 期」。

### 4.4 立即还款

- 元素 `RP-BTN-PAY`：`o_orderStatus != 4` 才显示。
- 勾选剩余解析后 `<= 0`：仍允许进入确认页，但确认页须按 §8.2～§8.3 拦住申请（或详情就 Toast，二选一：**默认详情仍进入确认页**，与「看渠道/复制账户」兼容）。
- 点历史 `RP-BTN-HISTORY`：任何状态都可进还款历史。

## 6. 还款渠道

### 6.1 渠道对象消费

| 字段 | 用途 |
|-----------|------|
| `o_icon` | 图标；失败占位 |
| `o_channelTypeName` | 渠道下拉**优先**展示名；空则用 `o_channelName` |
| `o_channelName` | 下拉兜底展示名；申请入参渠道名 |
| `o_channelCode` | 申请必传 |
| `o_status` | `"1"` 禁用，不进 Tab |
| `o_channelType` | `"0"` 现金/线下组、`"1"` 线上、`"3"` 可出现（勿当 Bre-B 丢）、`"4"` DEBIN；`"2"` 对公见 §6.5（后台正常不下发，误下发兜底）。本包无 Bre-B（后台不下发） |
| `o_channelTypeMsg` | Tab 文案与去重键；**不要**用本字段生成下拉文案，也**不要**用它判断 DEBIN |
| `o_orderType` | `"1"` 固定账号；其它按跳转申请 |
| `o_channelAccount` | 固定账户复制内容 |
| `o_channelRate` | **不读** |
| `minAmount` / `o_minAmount` | 线上申请下限 |
| `o_minRepaymentAmount` | 可展示；申请下限仍以 `minAmount` 为准，两者冲突停问 |
| `o_mark` | 原样上送 |
| `o_banks` | **不读**；选渠不做下拉；申请不带银行字段（见 §6.6） |
| `weight` / `sort` | **不在客户端重排**；Tab/列表保接口过滤后顺序 |

### 6.2 Tab、下拉与选中

1. 过滤启用渠道（丢弃 status=1、typeMsg 空；**保留** type=`3`，勿当 Bre-B 丢）。
2. Tab = 各渠道 `o_channelTypeMsg` trim 后首次出现顺序（不写死类型顺序，不用 `o_channelType` 分组）。
3. **进入确认页**：选中渠道 = 过滤后列表**第一项**；当前 Tab = 该项的 `o_channelTypeMsg`。
4. **下拉范围**：仅展示与**当前 Tab** 同 `o_channelTypeMsg` 的启用渠道（保接口顺序）。不是把过滤后全量渠道塞进一个下拉。
5. **下拉文案**：`o_channelTypeName` 非空用它，否则 `o_channelName`。
6. **切 Tab**：选该 Tab 下第一条渠道；输入若已 >0 则 cap 到基数，否则填基数。不因换渠道改金额公式。
7. **下拉改选**：同 Tab 内换一项 → 更新当前选中渠道；金额规则同第 6 点；再按该项 `o_orderType` / `o_channelType` 切换 §6.3～§6.5 UI（固定账户 / DEBIN 说明等）。
8. 无任何启用渠道：仍展示确认页；主按钮点了 Toast「请选择还款方式」类文案（§15），不申请。

> **`o_channelTypeMsg` 只是 Tab 展示名。** 接口可能下发 `Transferencia` / `QRCode` / `DEBIN` 等文案，**禁止**用文案含 `QR` / `Transferencia` / `DEBIN` 硬判业务。确认页特殊 UI **只**看选中渠道的：`o_channelType=="4"`→§6.3 DEBIN；`o_orderType=="1"`→§6.4 固定账户；其余（含常见线上 `o_channelType=="1"` 且 `o_orderType!="1"`，无论 Tab 是否叫 QRCode）→ 普通立即支付走 §9。QR / Transferencia **没有**独立的 `o_channelType` / `o_orderType` 枚举值，也不另绑一套确认页画板逻辑。

### 6.3 DEBIN

`o_channelType == "4"`：可展示说明折叠/「去查看」弹层（文案待 UI）。申请仍走 §9 线上分支（有 URL 则 Web）。**禁止**用 Tab 西语包含 `DEBIN` 做判断。

### 6.4 固定账户 `o_orderType == "1"`

- 展示 CVU/账号 = `o_channelAccount`（空则展示空并禁用复制）。
- 复制到剪贴板；成功提示待 UI。
- 隐藏立即支付。用户银行 App 转账后回本 App，靠首页/账单刷新看结果（本包无确认中付款记录页）。
- 不调 `/repayment/apply`。

### 6.5 对公 `o_channelType == "2"`（兜底）

**备注：** AR 后台正常**不返回** type=`2`（本包无对公银行链）。过滤规则**不要**丢掉 type=`2`。

若误下发仍进 Tab；本包**不做** §10 页，主按钮**不**进线下银行列表 / 详情 / 凭证上传：

| 条件 | 行为 |
|------|------|
| `o_orderType == "1"` | 走 §6.4 固定账户（展示/复制，不申请） |
| 其它 | 确认页申请走 §9（有 `o_redirectUrl` 则 Web） |

### 6.6 渠道配置银行 `o_banks`（本包不消费）

- 选渠 UI **不做** `o_banks` 下拉（类型 Tab + 渠道下拉即可）。

## 8. 金额

### 8.1 基数

确认页 `base` = 入口带来的勾选剩余或整单剩余。之后改渠道都不改 `base`。

### 8.2 输入

- 默认输入 = `base`。
- 用户输入只留数字，按本包金额输入过滤。
- 大于 `base`：拒绝写入并 Toast 超额文案。
- 申请 `o_amount` = 当前输入向下取整到整数串；`<= 0` 不得申请。
- 不读 `o_channelRate`，不加价，不减价。

客户端不得改详情 `o_loanLeftAmount`。

### 8.3 下限

- 线上/DEBIN：输入 < 当前渠道 `minAmount`（空当 0）→ Toast 最低额，不申请。
- 本包无凭证页、无对公线下银行项费率比较。

## 9. 还款申请 `POST ori: /repayment/apply`

未选渠道或固定账户模式：不调用。

### 9.1 线上/DEBIN 请求

|-----------|------|

| `o_userId` | 会话 |
| `o_amount` | 输入金额整数串 |
| `o_checkLoanLeftAmount` | 进入确认时的 `base` |
| `o_channelCode` | 当前渠道 |
| `o_channelName` | 当前渠道 |

不传：`o_bankName` / `o_bankCode` / `o_bankCardId`（本包不消费 `o_banks`）、凭证、付款人、还款时间、流水号、`o_refreshFlag`、`o_repaymentFee`。

### 9.2 线上成功
