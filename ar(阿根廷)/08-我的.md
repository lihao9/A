## 写法约定

1. 接口路径写作 `ori: /xxx`；实际 path 从 `00` §6 映射。
2. 字段只写 `o_xxx`；真实 wire 从 `00` §6 本包 API 映射。符号、分层、菜单本地 key 按约定 §3 自定。禁止对照工程混淆字段。
3. `M-*` 只是文档职责 ID。
4. H5 完整 URL = `00` §3 的 `webBaseUrl` + 对应路径；未填路径则 Web 入口做了也打不开，实现前停问。
5. 已锁定：本模块**不复制** 05 卡列表、07 还款申请、09 埋点 SDK。

## 1. 关键定论

1. 我的页只在**已登录**时出现。数据用当前内存里最近一次成功的 `ori: /main/base/info`（与首页同一对象），不单独再定义一套用户资料接口。
2. 切到我的 Tab **不强制**重拉首页；下拉刷新与 03 相同：拉 `ori: /user/base/info` + `ori: /main/base/info`。
3. 待还总额展示 `o_totalAmount`；空当 `"0"` 再格式化。点击整块进借款历史，**不**用该金额做筛选。
4. 点银行卡：打开 05，传入当前这份首页里的 `o_creditStatus`（缺省 `0`）。本页不拉卡列表。
5. 账户安全菜单：仅当 `o_loginPwd == true` **或**（`o_traderPwd == true` **且** `o_creditStatus == 2`）时插入菜单第一项。两项开关分别控制安全页内的行。
6. 借款历史点单分流与 **03 账单卡同一套 `o_orderStatus`**，进 06 或 07。**不因期数=1 跳过账单详情直接确认还款**（与首页待还入口对齐）。
7. 退出登录：**无**登出业务接口。清会话 token/userId/手机号（`00` §8 会话槽），回 02 手机号页，首页容器回到未登录。不在此清授信草稿（与 04「不因登出清草稿」一致）。
8. 注销：先本地提示弹层 → `ori: /user/judge/account/cancel` 成功才能进验证页。有在贷等业务失败：留我的页，Toast 服务端 message。
9. 注销验证码类型 **`6`**。提交 `ori: /user/account/cancel`（App，不走落地页接口）。成功清会话并进成功页；成功页返回/主按钮都进 02。
10. 意见反馈字典 type 参考 **`14`**；选项 key 逗号拼接；`key=="99"` 为其它，须填说明。`o_source` 固定 `"home"`。
11. 联系我们一次拉字典 types：`18` 邮箱、`17` WhatsApp、`23` 官网、`24` 地址（以本包字典为准）。每类只取**第一条**。
12. 不在我的页做优惠券、续期、改头像上传、消息中心。稿面多出入口则停问。

## 2. 我的页结构 `M-PAGE-ROOT`

在 03 的主 Tab 容器里（至少含首页/我的，具体以 UI 稿为准），不作为独立「再套一层首页」。

| 区域 | 元素 | 规则 |
|------|------|------|
| 顶栏 | 无返回 | 与首页一样不显示左返回 |
| 顶栏 | `M-ENTRY-SERVICE` | 进联系我们，与 `H-ENTRY-SERVICE` 同一职责页 |
| 头 | `M-IMG-AVATAR` | 占位切图，不可换头像 |
| 头 | `M-TEXT-TITLE` | 稿面标题 |
| 头 | `M-TEXT-PHONE` | 会话手机号掩码；规则跟实现用 UI（至少隐藏中间位） |
| 双入口 | `M-ENTRY-CONTACT` | 联系我们 |
| 双入口 | `M-ENTRY-BANK` | 05 列表 + `o_creditStatus` |
| 待还卡 | `M-ENTRY-HISTORY` | 展示 `o_totalAmount`；点进历史 |
| 菜单网格 | `M-MENU-*` | §3 |

默认：顶栏固定、内容可滑、底部 Tab 仍是 03 的。可下拉刷新。

## 5. 联系我们 `M-PAGE-CONTACT`

`POST ori: /tools/dict`，types = `18,17,23,24`（一次）。

每类 `firstOrNull`。空类不占位。列表顺序按 types 数组。

| type（参考） | 行为 |
|--------------|------|
| `18` 邮箱 | 展示；点复制 |
| `17` WhatsApp | 展示；点系统打开 WA（号为字典 value；打不开则复制+Toast） |

## 6. 借款历史 `M-PAGE-LOAN-HISTORY`

### 6.1 请求 `POST ori: /bill/list`

| 字段 | 取值 |
|------|------|
| `o_userId` | 会话 |
| `size` | `600` |
| `current` | `1` |
| 还款/打款状态数组 | **不传**（全量） |

不做分页加载更多。下拉刷新重拉。`data=null`：当空列表，不清崩溃。

### 6.2 响应

| 字段 | 用途 |
|-----------|------|
| `o_totalAmount` | 页内总额（可展示）；与我的卡不必强校验相等 |
| `o_loanList` | 订单数组，服务端顺序 |
| `total` / `pages` | 不用于翻页 |

### 6.3 每条至少消费

与 03 账单卡同语义的：

| 字段 | 用途 |
|-----------|------|
| `o_loanId` | 跳转 |
| `o_orderStatus` | 0 打款中 / 1 失败 / 2 待还 / 3 逾期 / 4 结清 |
| `o_orderAmount` 或 `o_loanLeftAmount` | 主金额：未结清优先剩余，结清用订单金额；以确认 UI 为准，**不要两套都猜**。默认：**未结清展示 `o_loanLeftAmount`，结清展示 `o_orderAmount`** |
| `o_orderTime` / `o_orderDueDays` | 时间条文案同 03 §5.2～5.3 |
| `o_repayPercent` | status∈{2,3,4} 显示进度 |
| `o_planSimpleList` | 期次摘要，字段同 03 §5.6 |
| `o_failureReason` | 仅失败跳 06 失败页时带上 |

不读优惠券、续期。

### 6.4 点击

整卡与主按钮同一套分流（不因「点的是按钮还是卡片」改路由）：

| `o_orderStatus` | 去向 |
|-----------------|------|
| `0` | 06 打款处理中（不调预览） |
| `1` | 06 打款失败，带 `o_failureReason` |
| `2` / `3` / `4` | 07 账单详情，只传 `o_loanId` |
| 其它 | 不跳转；可 Toast 刷新 |

空 `o_loanId`：不跳转。

## 7. 账户安全 `M-PAGE-SECURITY`

路由带入两个布尔：登录密码行、交易密码行（进入时快照）。页内：

| 行 | 条件 | 去向 |
|----|------|------|
| 修改登录密码 | 登录开关 true | 02 重置登录密码页；带会话手机号；type=`2`；**无**渠道选择，规则全抄 02 §6.9 |
| 修改交易密码 | 交易开关 true（已含授信成功） | 本模块重置交易密码页 |

两行都 false：不应进入本页（菜单已隐藏）。

### 7.1 重置交易密码 `M-PAGE-RESET-TPWD`

发码类型与 02 交易密码重置一致（参考 type=`3`，以本包短信 type 枚举为准）。页上：OTP、两次新 4 位交易密码、**DNI 8 位**（与 04 相同，不补 0）。

提交 `ori: /user/trader/password/reset`：

| 字段 | 取值 |
|------|------|
| `o_userId` | 会话 |
| `o_mobile` | 手机号 RSA |
| `o_password` | 新密码 RSA（确认格只本地比对） |
| `o_verCode` | OTP |
| `o_verImageCode` | 需要图形码时 |
| `o_idNumber` | DNI 明文或本包规定格式 |
| `o_type` | `"1"`（重置；首次设置 `"0"` 只属于 06） |
| `o_mobileSn` | 本包设备 id |

成功：pop 回安全页或我的；Toast 服务端或 UI 成功文案。失败挂 DNI 或全局 message，以接口为准。密码不写日志、不持久化明文。

## 8. 意见反馈 `M-PAGE-FEEDBACK`

进页拉 `ori: /tools/dict` type=`14`。项：`key` 提交、`value` 展示。可多选。

- 未选任何项：不提交，Toast 必选。
- 含 `99`：说明 trim 必填。
- 不含 `99`：说明可空。

`POST ori: /help/feedback/add`

| 字段 | 取值 |
|------|------|
| `o_userId` | 会话 |
| `o_source` | `"home"` |
| `type` | 选中 key 英文逗号拼接，无空格 |
| `content` | 说明 trim；无则 `""` |

成功：Toast 后 pop。不上传图片（稿面有图则停问）。

## 11. 注销

### 11.1 提示 `M-DIALOG-DELETE-TIPS`

### 11.2 预检 `POST ori: /user/judge/account/cancel`

|------|------|

### 11.3 验证页 `M-PAGE-DELETE-OTP`

展示会话手机号（可部分高亮）。OTP 输入与发送复用 02 能力：图形码、倒计时、长度。短信 type=**`6`**。

`POST ori: /user/account/cancel`

| 字段 | 取值 |
|-----------|------|
| `o_userId` | 会话 |
| `o_mobile` | RSA 手机号 |
| `o_verCode` | OTP |
| `o_verImageCode` | 有则传 |
| `o_mobileSn` | 设备 id |
| `o_source` | `1`（App） |
| `o_pageId` | `"3"`（验证码页；若联调只认 `"1"` 再改本文） |
| `o_cancelCode` / `o_cancelReason` | 不传（无挽留选项页）。字典 `25` 本包不做除非 UI 增加 |

不调落地页注销接口。

成功：清会话 → `M-PAGE-DELETE-OK`（pop 验证页）。失败留验证页。

### 11.4 成功页

不可回我的。返回/主按钮 → 02。系统返回同样。
